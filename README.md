# ELSOLTEC 업무 보드

Windows/Linux에서 실행하는 회사 그룹웨어 개발 버전입니다. Node.js 24 이상과 내장 SQLite를 사용하며 메일 송수신 및 엑셀·서명 기능에 Nodemailer·Mailparser·ExcelJS·image-size 패키지를 사용합니다. 첫 실행 시 자동 설치하거나 `npm ci`로 설치하세요. 계정·결재·프로젝트·고객사·회계 기록은 `data/group.db`에 저장합니다.

## Windows 간편 실행

1. ZIP을 **모두 압축 해제**하고 Node.js 24 이상을 설치합니다.
2. 기존 사용자라면 이전 서버를 Ctrl+C로 종료하고 **기존 data 폴더를 새 프로젝트 폴더로 복사**합니다. 원본을 삭제하지 마세요.
3. 처음 사용한다면 `CREATE-ACCOUNT.cmd`로 계정을 생성합니다. 최초 관리자는 `soltec@elsoltec.com`, 역할은 manager로 입력하세요. 비밀번호는 직접 정하며 기본 비밀번호는 없습니다.
4. `START-LOCAL.cmd`를 실행하고 `Groupware started`가 나오면 Edge에서 `http://127.0.0.1:3000`을 엽니다.
5. 업데이트 후 Ctrl+F5로 새로고침합니다. 기존 아이디·비밀번호는 그대로 사용합니다.

명령 파일은 프로젝트 폴더의 data를 사용하고 로컬 테스트용으로 HOST/OFFICE_IP를 127.0.0.1로 설정합니다. 실제 회사 운영 설정과 다릅니다. Windows 명령 파일 자체는 현재 Linux 환경에서 실행 검증하지 못했습니다.

직접 실행하려면 프로젝트 폴더에서 `npm ci` 후 `npm test`, `npm start`를 실행합니다.

## 관리자와 결재 역할

`soltec@elsoltec.com`의 기존 활성 계정은 새 버전 시작 시 **한 번만** manager/최초 Admin으로 지정합니다. 계정이 없다면 계정을 먼저 만들어야 하며 임의 비밀번호로 자동 생성하지 않습니다. 기존 비밀번호는 변경하지 않습니다. 이후 지정은 사용자 관리에서 합니다. 마지막 활성 Admin의 해제·비활성화는 차단합니다.

- 결재 역할: employee(직원), manager(이사), ceo(대표이사).
- Admin은 별도 권한으로, 다른 계정에도 지정할 수 있습니다. Admin만으로 결재 역할이 바뀌지는 않습니다.
- **이사은 본인이 상신한 휴가·지출·기안도 이사 단계에서 승인할 수 있습니다.** 대표 최종 승인 단계는 유지합니다. 대표이사도 본인 문서의 대표 단계에서 최종 승인할 수 있습니다.
- 회계는 결재 역할이 이사/대표이사인 사용자만 접근·조회·작성·수정·삭제할 수 있습니다. Admin 권한만으로 회계 접근은 허용하지 않습니다. 일반 직원은 본인 프로필·아이디만 수정하고 계정 생성·권한 변경·다른 사용자 관리 API에는 접근할 수 없습니다. 프로젝트는 모든 사용자가 공동 관리합니다.
- 사용자 권한/상태/비밀번호 변경 시 해당 계정의 로그인 세션을 종료합니다.

이 정책은 이전 문서에 남아 있는 ‘이사 본인 승인 차단’ 설명을 대체합니다.

## 계정 생성과 복구

서버 운영자 CLI 예시입니다. 비밀번호를 명령행 인수나 저장소에 기록하지 마세요.

```powershell
$secret = Read-Host '초기 비밀번호(12자 이상)' -AsSecureString
$env:NEW_USER_PASSWORD = [System.Net.NetworkCredential]::new('', $secret).Password
npm.cmd run user:add -- soltec@elsoltec.com '이사' manager
Remove-Item Env:NEW_USER_PASSWORD
```

이미 존재하는 계정은 다시 만들지 않습니다. Admin 로그인 후 사용자 관리에서 새 계정과 권한을 관리할 수 있습니다. 초기화한 비밀번호는 별도의 안전한 경로로 대상자에게 전달하세요.

운영자 CLI:

```sh
node server.js user:disable staff01
node server.js user:enable staff01
node server.js user:role staff01 manager
```

2단계 인증은 사용자 요청에 따라 제거했으며 아이디·비밀번호로 로그인합니다. 보안 설정에서 비밀번호 변경 시 모든 세션이 종료됩니다.

## 데이터와 업데이트

스키마 변경은 기존 DB에 테이블/열을 추가하는 방식입니다. 프로젝트 수행 이력, 명함 이미지, 회계 전표, 사용자 권한도 같은 DB에 저장하며 백업에 포함됩니다. 운영 DB/비밀번호는 GitHub와 배포 ZIP에 포함하지 않습니다.

기존 최종 승인 지출은 첫 실행 시 중복 없이 회계 미지급 전표로 가져옵니다. 과거 실제 지급 여부는 자동으로 알 수 없으므로 운영자가 확인하고 지급 기록을 남겨야 합니다. 이사 승인만 된 지출은 아직 회계에 반영하지 않습니다.

## 백업과 복원

```sh
node scripts/database.js backup data/group.db /private-backups/group-20261027.db
node scripts/database.js restore /private-backups/group-20261027.db /private-data/group-restored
```

경로를 운영체제에 맞게 바꾸세요. 백업은 온라인 SQLite API로 WAL 변경도 포함하며 기존 파일을 덮어쓰지 않습니다. 복원은 새 디렉터리로만 수행하고 복원본의 모든 로그인 세션을 삭제합니다. 원본 서버 중지 후 DATA_DIR을 복원본으로 바꿔 재시작하세요. 기존 원본 데이터는 삭제하지 않습니다.

DB에는 개인정보·명함·재무 데이터·비밀번호 해시가 있으므로 제한된 권한과 암호화된 별도 저장소로 백업하세요. 외부 저장소/자동 백업 스케줄은 아직 구성하지 않았습니다.

## 환경 설정과 배포

- DATA_DIR: 기본 프로젝트의 data, 운영 시 절대 경로의 영구 저장소 지정.
- HOST/PORT: 기본 127.0.0.1/3000.
- OFFICE_IP: 운영 기본 220.120.152.40. 로컬 테스트 런처만 127.0.0.1.
- PUBLIC_ORIGIN: 실제 HTTPS 출처.
- NODE_ENV=production: HTTPS 전용 Secure 쿠키 적용.
- TRUSTED_PROXY_IPS: 기본 빈 값. 직접 연결 IP가 신뢰 목록에 있을 때만 단일 X-Real-IP를 사용합니다.

`deploy/Caddyfile`과 `production.env.example`은 같은 서버의 Caddy→Node 루프백 구성을 위한 예시입니다. 실제 도메인 DNS, HTTPS 인증서, 80/443 방화벽을 준비하고 Node 포트는 외부에 직접 노출하지 않습니다. Caddy는 X-Real-IP를 실제 접속 주소로 덮어써야 합니다. 검증 예: `caddy validate --config deploy/Caddyfile --adapter caddyfile`. CDN/컨테이너/추가 프록시가 있으면 실제 주소 정책을 다시 검증하세요. VPN이 사무실 IP를 공유하면 사외 출퇴근을 구분할 수 없습니다.

실제 HTTPS 배포·Caddy 인증서 발급·Windows PWA 설치는 미검증입니다. 현재는 내부 검토용입니다. PWA 설정·아이콘·설치 버튼은 제공하며 업무 정보는 오프라인 캐시에 저장하지 않습니다.

## 사용자 프로필과 일정 참여 인원

사용자 관리 메뉴는 모든 로그인 계정에서 사용할 수 있습니다. Admin은 전체 사용자를 생성/수정하고 일반 계정은 본인 정보만 조회·수정합니다. 직급은 대표이사·이사·본부장·연구소장·부장·차장·과장·대리·사원 중 선택하며 소속은 경영본부·기업부설연구소·사업본부·기술개발본부입니다. 이름·전화번호·이메일을 함께 저장합니다. 이 프로필 정보와 결재 역할/Admin 권한은 별개이며 개인이 권한을 바꾸는 요청은 차단합니다.

일정 등록/수정의 **참여 인원** 탭에서 이름·조직·직급·이메일로 활성 사용자를 찾아 복수 선택합니다. 개인 일정에서 참여자를 선택하면 작성자/선택 인원만 보는 **참여자 공유**로 전환합니다. 회사 일정은 여전히 직원 전체에게 공개됩니다. 참여자는 자신의 캘린더에서 내용을 조회·수정할 수 있습니다. 참여 인원·공개 범위 변경은 작성자 또는 Admin, 삭제는 작성자만 가능합니다. 사용자 이름/직급/조직 변경은 기존 일정의 참여자 표시에도 반영됩니다. 이메일 알림 발송이나 참석 수락/거절은 아직 없습니다.

기존 프로필에 없던 값은 빈 상태로 보존합니다. 사용자 관리에서 처음 수정할 때 직급·조직·전화번호·이메일을 입력하세요. 로그인 아이디는 이메일 프로필 수정으로 바뀌지 않습니다. 기존 계정/결재/프로젝트/회계/일정은 유지하며 참여자 관계도 DB 백업에 포함됩니다.

## 공동 편집·프로젝트 달력 · 최신 변경

- 일정 목록의 **일정 수정** 또는 달력 항목을 눌러 수정합니다. 회사 일정은 로그인 직원이, 참여자 공유는 작성자와 선택된 참여자가 내용을 수정할 수 있습니다. 개인 일정은 작성자만 접근합니다.
- 일정 등록/수정에서 **연결 프로젝트**를 선택합니다. 연결 일정은 프로젝트 달력에도 표시하고 클릭해서 수정합니다. 일정 목록에서 연결 프로젝트로 이동할 수 있습니다. 개인 일정이 프로젝트와 연결되어도 다른 직원에게 공개되지는 않습니다.
- 모든 로그인 사용자가 프로젝트 이름/고객사/기간/설명/상태와 공정을 수정할 수 있습니다. 수정 기록과 버전 충돌 검사를 적용합니다.
- 공정은 시작일~종료일이 있는 월별 달력으로 표시합니다. 날짜를 눌러 등록하고 항목을 눌러 수정·수행 내역을 기록합니다. 이전 주간 공정은 해당 주와 프로젝트 기간의 겹치는 구간으로 옮겨 진척·이력을 유지합니다.
- 1차 결재 역할 명칭은 **이사**, 최종은 **대표이사**입니다. 기존 manager 코드와 계정은 유지하고 표시 명칭을 바꿉니다. 프로필의 직급 수정만으로 권한을 얻지 않으며 Admin이 결재 역할을 지정합니다.
- 이사와 대표이사 모두 본인 문서의 해당 단계에서 승인할 수 있습니다. 대표이사 본인 문서도 이사 단계를 먼저 거칩니다.
- 지출결의서(연구개발비/기존 연구비)는 신규 작성 목록과 작성 API에서 제외합니다. 기존 문서·결재·회계 이력은 보존하고 일반 지출결의서는 유지합니다.

## 외부 메일 · 회사 로고 테마

이메일 메뉴에서 POP3 수신, SMTP 발신, 첨부파일 송수신을 지원합니다. 계정 추가에서 카페24 메일 비밀번호를 입력하세요. 상단과 좌측 회사 로고, 흰 배경과 태양 심볼 색상 테마를 적용했습니다. 설정·제한·암호화 키 백업은 [메일 업데이트 안내](docs/MAIL-UPDATE.md)를 확인하세요. `data` 폴더 전체를 유지해야 합니다.

## 화면 정리 · 시계와 공정 완료 체크

상단 가로 메뉴바를 제거하고 최상단 문구를 WORKSPACE로 변경했습니다. 전체 메뉴는 좌측 버튼과 F3에서 열 수 있습니다. 좌측 반복 로고/WORKSPACE 자리에는 한국 시간 아날로그 시계와 현재 달·다음 달의 작은 달력을 표시합니다. 화살표로 월을 이동하고 월 제목을 누르면 해당 월의 일정관리가 열립니다. 작은 화면에서는 시계/작은 달력을 접어 메뉴 공간을 확보합니다.

신규기안 하단의 승인 메뉴는 **결재 대기**로 표시합니다. **결재 운영 조회는 Admin만** 화면과 API에 접근할 수 있으며 일반 이사·대표이사 계정은 접근할 수 없습니다. 문서 승인 권한·결재 순서는 그대로 유지합니다.

공정 등록/수정과 공정 달력에서 완료 여부를 체크할 수 있습니다. 체크하면 해당 공정 100%, 해제하면 예정 0%로 저장하고 수행 이력을 남깁니다. 중간 진척률은 공정 수정에서 입력합니다. 프로젝트 전체 진척률은 공정 진척률의 단순 평균이며 완료 개수와 진행 막대를 함께 표시합니다. 공정 기간이 여러 날이어도 전체 평균에는 한 번만 반영합니다. 전체 진척률이 100%여도 프로젝트 상태는 별도로 관리합니다. 기존 공정과 수행 기록은 보존합니다.

검증: `npm test` 20개, `scripts/workspace-smoke.mjs`의 시계 갱신/달력 이동/Admin 접근 제한/공정 체크·해제/평균 진척률/새로고침 보존/모바일 화면 검사.

## 글꼴

전체 화면·입력창·버튼·표·달력·메일 본문에 Noto Sans KR 가변 글꼴(굵기 100~900)을 적용했습니다. Google Fonts 공식 저장소의 폰트를 `public/fonts/NotoSansKR-Variable.ttf`에 포함해 외부 폰트 서비스 접속 없이 제공합니다. 최초 로딩에는 약 10MB의 폰트 파일을 불러옵니다. 로고 이미지는 제공된 회사 디자인을 유지합니다. 글꼴 라이선스는 `public/fonts/OFL.txt`(SIL Open Font License 1.1)에 포함했습니다.

## 사용자 영구 삭제 · 회계 CRUD · 개인 메일함

Admin 전용 사용자 생성·권한 관리·영구 삭제, 본인/관리자의 아이디 변경, 이사·대표이사 전용 회계 수정·삭제, 개인 메일함과 자동 분류 및 20~100개 표시 설정을 제공합니다. 사용 방법과 삭제 범위는 [권한·메일 관리 안내](docs/ACCESS-MAIL-MANAGEMENT.md)를 확인하세요. 사용자 삭제는 현재 그룹웨어 DB의 연결 자료를 보관 없이 제거하며, 과거 별도 백업과 외부 카페24 원본은 대상에 포함하지 않습니다.

## 업무보고 · 보라색 기본 테마

업무보고에 **교육계획서·교육보고서·회의록·일일업무일지** 4개 양식과 이사→대표이사 결재함을 추가했습니다. 일일업무일지는 제공 이미지의 실시/예정 좌우 배치와 진행업무/특이사항을 반영합니다. 전체 기본색은 로고의 보라색이며 각 메뉴는 파랑·녹색·주황·노랑·붉은색·하늘색 계열로 구분합니다. [양식·결재·테마 안내](docs/WORK-REPORTS.md)에 사용법과 웹 양식 조사 제한을 기록했습니다.

## 바형 메뉴 · 대표 결재 전 문서 삭제

좌측 메뉴를 한 줄에 하나씩 가로 바로 배치하고 상단/좌측 메뉴에 입체감을 적용했습니다. 모든 결재 문서는 대표이사 승인·반려 전까지 작성자 또는 Admin이 상세 화면에서 삭제할 수 있습니다. 이메일 왼쪽 **＋ 메일함 만들기**에서 일반 사용자도 개인 메일함을 바로 생성합니다. [삭제 가능 범위와 사용법](docs/NAVIGATION-DOCUMENT-DELETE.md)을 확인하세요.

## 자동 확장 양식 · 엑셀 · 결재 이미지

좌측 **전자결재**를 클릭하면 신규기안과 양식 목록이 펼쳐집니다. 긴 내용 입력칸은 입력량에 따라 높이가 늘어나며 모든 전자결재·업무보고 양식을 작성 중 또는 저장 후 **엑셀 다운로드**할 수 있습니다. 이사·대표이사 전용 **서명·도장 등록** 메뉴에서 이미지를 등록하면 이후 결재에 날짜·이미지·이름을 보존하고 엑셀에도 포함합니다. [설정·다운로드·보존 안내](docs/FORMS-EXCEL-SIGNATURES.md)를 확인하세요. 이번 버전은 패키지가 추가되었으므로 직접 실행할 때는 먼저 `npm.cmd ci`를 실행하세요.
