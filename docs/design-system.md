# UI 디자인 원칙

- 기존 업무 흐름과 메뉴 배치는 유지하고 `public/design.css`에서 공통 표면·색상·타이포그래피를 정의합니다.
- 밝은 회색 배경, 흰 카드, 중립 테두리와 약한 그림자를 사용합니다. 모듈별 색상은 선택된 메뉴와 주요 동작에 유지합니다.
- 글꼴은 로컬 Pretendard가 있으면 사용하고, 기본 배포에서는 포함된 Noto Sans KR을 사용합니다. 외부 폰트 요청은 필요하지 않습니다.
- 상태는 파스텔 배경과 진한 텍스트로 표현합니다. 키보드 포커스를 표시하고 reduced-motion 설정에서는 애니메이션을 끕니다.

## 프로젝트 차트

- 상단 도넛과 중앙 숫자는 선택한 프로젝트의 진척률을 표시합니다. 공정마다 동일 비중의 구간을 배정하고, 각 구간을 해당 공정의 실제 진척률만큼 채웁니다. 공정 ID로 정한 안정적인 색상을 비교 그래프에도 사용하고 잔여 부분은 중립 회색으로 표시합니다. 프로젝트 카드·연결 일정의 프로젝트 색상은 별도로 유지합니다.
- 프로젝트 진척률은 서버가 계산한 각 공정 진척률의 단순 평균을 반올림합니다. 기존 계산식과 동일하며 완료 공정 개수 비율과 다릅니다.
- 공정이 없으면 0%와 빈 상태를 표시합니다. 프로젝트명, 상태, 완료/전체 개수와 접근성 텍스트를 함께 제공합니다.
- 상단 중앙은 0~100% 공통 기준의 세로 컬럼 차트, 오른쪽은 최신 등록순 수행 내역입니다. 컬럼 너비와 간격을 고정하고 많은 공정은 가로 스크롤로 표시합니다. 수행 내역은 116px 기본 카드 두 개와 12px 간격을 담는 244px 목록에서 스크롤합니다. 긴 내용은 줄바꿈하며 전체 정보는 공정 상세에서도 확인합니다.
- 프로젝트 목록과 엑셀 보고서는 같은 서버의 공정 완료 계산과 전체 평균 진척률을 사용합니다. 엑셀은 조회 월/목록 표시 개수와 무관하게 선택 프로젝트의 전체 공정·수행 기록·일정 변경 기록을 제공합니다.
- 캘린더는 선택한 조회 월을 유지하며 날짜별 완료 체크와 상세 열람을 제공합니다. 중복된 전체 진척률 막대는 표시하지 않습니다.

## 검증

공통 본문 간격은 `--workspace-gap`(데스크톱 24px, 모바일 16px)으로 관리합니다. 홈은 실제 상단 요소 높이를 측정해 달력을 맞추고, 홈·일정관리 날짜별 일정 목록에는 독립 스크롤을 적용합니다. 일정관리 하단은 기본 접힘 상태의 한국 시간 기준 일요일~토요일 주간 목록입니다.

전자결재·업무보고·사용자는 첫 클릭에 기본 화면으로 이동하고 같은 화면에서 다시 누르면 우측 하위 메뉴를 엽니다. 아이콘·라벨·화살표는 독립된 열이며 사용자 라벨은 CSS 자간으로 네 글자 라벨과 같은 시각적 폭을 사용합니다.

`npm test`, `scripts/project-report-navigation-smoke.mjs`, `scripts/workspace-v2-smoke.mjs` 등으로 검증합니다. 최신 변경 및 검증 내역은 [세로 그래프·엑셀 보고서·우측 메뉴 검증](project-report-navigation-review.md)에 기록합니다.
