# 세로 공정 그래프·프로젝트 엑셀 보고서·우측 하위 메뉴

기준 커밋: `5148be9d74a70566ca0398fce1238e3cf7e4aedb`. 작업 시작 시 로컬 변경은 없었고 원격 main도 같은 커밋임을 확인했습니다. 데이터 마이그레이션이나 기존 저장 데이터 수정은 없습니다.

## 요구사항별 구현

1. **세로 공정 그래프**
   - 선택 프로젝트의 공정 하나당 컬럼 하나. 공통 0~100% 축, 25% 간격의 연한 보조선, 위쪽 정확한 퍼센트, 아래쪽 줄바꿈 공정명.
   - 실제 플롯 높이 140px에서 0/65/100%는 각각 0/91/140px. 100% 숫자를 위한 상단 여유 24px. 공정 버튼 너비 88px, 간격 8px로 고정하며 많은 공정은 내부 가로 스크롤.
   - 원형 그래프와 동일한 공정 ID 기반 색상. 긴 공정명은 최대 세 줄과 전체 이름 툴팁/접근성 이름, 기존 상세 화면으로 확인. 방향키·Home·End·Enter로 이동/열기.
   - 세 패널 높이 322px, 수행 내역 두 카드 기준 244px 내부 스크롤 유지. 프로젝트 전환과 완료 체크·기간 변경 후 동일 데이터로 갱신, 기존 요청 순번 보호 유지.
2. **엑셀 보고서**
   - 워크보드 작업 버튼에 `엑셀 보고서` 추가. 프로젝트 미선택 안내, 생성 중 비활성/상태, 실패 원인 안내 제공. 생성 중 프로젝트를 바꿔도 클릭 시 선택한 프로젝트의 보고서를 받습니다.
   - `GET /api/projects/:id/excel`에서 전체 기간의 공정/기록을 다시 조회합니다. 화면의 조회 월, 스크롤, 두 카드 노출 제한을 사용하지 않습니다.
   - 기존 ExcelJS와 인쇄용 글자 폭 계산을 재사용합니다. 프로젝트 조회와 내보내기는 같은 공정 완료 계산 결과와 동일한 전체 평균 진척률을 사용합니다. 계산식과 체크 저장 방식은 바꾸지 않았습니다.
3. **세 부모 메뉴 동작 통일**
   - 다른 화면에서 첫 클릭 → 기본 화면. 기본 화면에서 재클릭 → 우측 메뉴. 열린 상태에서 재클릭 → 닫힘. 작성/설정 하위 화면에서 클릭 → 먼저 기본 화면으로 복귀.
   - 전자결재 12개, 업무보고 4개의 기존 서식과 권한에 따른 사용자 하위 메뉴 유지. 한 번에 하나만 표시하고 본문이나 좌측 다른 메뉴를 밀어내지 않습니다.
   - body에 고정 패널로 표시해 사이드바 스크롤에 잘리지 않습니다. 화면 경계에서 위치 보정, 내부 스크롤, 바깥 클릭/다른 메뉴/하위 선택/Esc/Tab으로 닫힘. Esc는 부모로, Tab은 다음 요소로 포커스 이동.
4. **화살표 정렬**
   - 세 부모 버튼을 아이콘 24px / 라벨 / 화살표 12px의 공통 grid로 배치합니다. 화살표는 12×12px 고정 영역이며 회전 전환 중 위치 변화를 없앴습니다.
5. **사용자 라벨**
   - 라벨 폭 4em과 CSS 자간 .5em으로 세 글자를 네 글자 메뉴와 비슷한 폭으로 표시합니다. 실제 문자열은 `사용자`, 글꼴/크기/굵기는 다른 메뉴와 동일하며 화살표 위치와 독립적입니다.

## 엑셀 시트와 인쇄 설정

| 시트 | 내용 |
|---|---|
| 프로젝트 보고서 | 이름·기관·기간·상태·전체 진척률·등록자·담당자·참여자·생성일시·설명 및 전체 공정 표 |
| 공정 수행 내역 | 실제 work 기록과 기존의 실제 legacy 기록. 수행일자·공정명·내용·작성자·기록 시각·기록 ID·구분 |
| 일정 변경 내역 | 공정명·변경 전후 기간·변경 사유·변경자·시각·기록 ID |

- 실제 `.xlsx` 파일. 일수는 정수, 진척률은 숫자 및 `0%` 형식. 날짜 문자열과 기록 시각은 한국 시간 기준. 파일명은 프로젝트명·생성일을 포함하고 금지 문자를 정리합니다.
- 사용자 입력은 ExcelJS 문자열로 기록하며 수식 객체로 만들지 않습니다. 단순 완료 체크나 공정 등록 이벤트를 수행 내용으로 꾸미지 않습니다.
- 장문은 그래핌 경계에서만 분할합니다. 분할된 내용 셀을 이어 붙이면 원래 저장된 문자열과 일치하며 한글·기호·이모지·줄바꿈·공백을 유지합니다. 같은 기록의 분할 행은 기록 ID로 구분할 수 있습니다.
- A4 가로, 폭 한 페이지(`fitToWidth=1`), 높이 제한 없음(`fitToHeight=0`), 여백/인쇄 영역/반복 표 헤더/헤더 고정/필터 적용. 장문 본문은 최대 네 줄의 작은 행으로 나눠 페이지 사이에서 이어집니다. 본문을 수직 병합하지 않습니다.
- 기록이 없으면 각 시트에 빈 상태를 명시합니다. 수행일자가 저장되지 않은 과거 기록은 `미기록`으로 표시하고 실제 기록 작성시각을 별도로 보존합니다.
- 권한은 기존 프로젝트 화면과 동일합니다. 현재 정책은 로그인한 활성 사용자의 프로젝트 공동 조회이며 별도의 프로젝트별 비공개 권한은 없습니다. 비로그인/비활성 계정은 서버에서 차단하고 연결 일정의 개인·초대 데이터는 보고서에 포함하지 않습니다.

## 코드 리뷰와 발견 문제 수정

- 공정명 줄 수에 따라 native button의 내용이 세로 중앙 정렬되어 컬럼 바닥이 달라졌습니다. 플롯과 공정명에 고정 grid 행을 적용하고 실제 DOM의 모든 막대 바닥 좌표가 동일한지 검사했습니다.
- 회전 중 화살표의 사각형 크기가 달라져 오른쪽 정렬이 움직였습니다. 정사각형 영역과 즉시 회전으로 보완하고 세 해상도의 오른쪽 여백/중심/라벨 폭을 비교했습니다.
- 포털 메뉴 마지막 항목에서 Tab을 누르면 브라우저 영역으로 포커스가 빠져 메뉴가 남을 수 있었습니다. Tab 닫기와 다음 요소로의 포커스 이동을 명시했습니다.
- 엑셀의 긴 표 헤더가 고정 높이에서 잘릴 수 있어 실제 줄 수로 헤더 높이를 계산합니다. 본문과 별개로 검증했습니다.
- 일반 목록과 보고서의 공정·진척률 조회를 공통 함수로 묶어 계산 중복을 제거했습니다. 전체 기록에 월 필터나 LIMIT가 없는지, 프로젝트 ID 범위와 인증 경계가 유지되는지 검토했습니다.
- 기존 기안 상신 이벤트, 보고서 제출, 사용자 관리 권한을 보존하고 실제 화면 동작으로 확인했습니다. 이전 가로 그래프와 펼침 목록을 전제로 한 테스트는 새 요구사항으로 갱신했습니다.

## 확인하지 못한 범위

- 환경에 Microsoft Excel/LibreOffice가 없어 **실제 Excel 인쇄 미리보기와 PDF 렌더링은 직접 검증하지 못했습니다**. XLSX 재열람, 보존 데이터, 행 높이, 페이지 나눔 XML 및 인쇄 설정까지 검증했습니다. 실제 출력 시 폰트/프린터에 따른 차이는 남아 있습니다.
- 브라우저는 Chromium 및 모바일 폭 에뮬레이션입니다. 실제 iOS/Safari/Firefox는 미검증입니다.
