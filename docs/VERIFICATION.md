# 로컬 ToDo 구현·검증 기록

> 이 문서는 0.1 당시 기록입니다. 현재 0.2의 기능·마이그레이션·검증 결과는 [V02-VERIFICATION.md](V02-VERIFICATION.md)를 먼저 읽으세요.

이 문서의 아래 본문은 취소 전 로컬 구현 검증 기록입니다. 이후 GROUP main에서는 ToDo를 제외한 상태를 유지했고, 보관된 ToDo를 별도 `todo-standalone` 다운로드 브랜치로 분리했습니다. 다운로드 패키지의 추가 검증은 [DOWNLOAD-VERIFICATION.md](DOWNLOAD-VERIFICATION.md)를 참고하세요.

확인일: **2026-11-19, 한국 시간**. 실제 연결된 저장소는 `https://github.com/byun712/GROUP`, 체크아웃은 `/workspace/GROUP`, 작업 브랜치는 `work`다. 시작 시 작업 트리는 깨끗했고 원격 fetch 결과 HEAD와 main은 `3e4e6930f70cda566036cec46e7d649e7a683223`로 일치했다. 이 버전의 ToDo는 별도 `todo/`에 구현했으며 GROUP 제품 파일과 운영 데이터를 수정하지 않았다.

## 실제 구현 범위

- 약 240px 좌측 메뉴, 24~32px 본문 여백, 목록 중심 PC 화면, 별도 스크롤의 우측 상세 패널.
- 할 일 등록/조회/수정/완료/복원/확인 후 삭제, 목록의 상태/우선순위/마감일 편집.
- 전체/오늘/예정/프로젝트/완료 보기, 오늘의 기한 지남 구분, 제목·설명 검색, 상태·우선순위 필터, 5종 정렬.
- 로컬 프로젝트/공정 등록·수정·삭제와 관계 검증, 연결 없는 개인 할 일.
- 여러 업무 수행 기록의 추가/수정/개별 삭제. 수행일·생성 시각·할 일 연결 보존. 실제 내용을 상태 변경에서 임의 생성하지 않음.
- IndexedDB 트랜잭션, 생성/수정/완료 시각, 탭 간 버전 충돌 검사, 실패한 입력 보존, 화면 설정, 명시적 예시 생성.
- JSON 내보내기, 검증 후 원자적 복원, 확인 후 ToDo 데이터만 초기화.
- 독립 Manifest·아이콘·범위가 제한된 SW·정적 자산 캐싱·업데이트 보호·지원 이벤트가 있는 경우에만 설치 버튼.

후속 범위: GROUP API/로그인/사용자 간 공유/서버 동기화/푸시, 모바일 최적화·모바일 PWA 실기기 검증, GROUP 보고서/엑셀 연결. 현재는 모두 연결되지 않았다.

## PWA 검증 방법과 범위

배포 빌드를 먼저 정상 로드하고 `/todo/` 서비스 워커 제어와 캐시 준비를 확인했다. 네트워크를 완전히 차단한 상태에서 다시 열어 조회·수정하고 새로고침 후 변경이 남는 것을 검증했다. 캐시는 `/todo/` 정적 파일 URL만 포함하며 `/api/` 호출이나 사용자 레코드를 캐시하지 않는다. 루트 `/`는 ToDo 서비스 워커의 제어 범위 밖이다. 개발 서버의 다른 origin에는 SW 등록이 없다.

내용 해시가 다른 두 번째 빌드를 배포하고 `registration.update()`로 대기 버전을 만들었다. 미저장 설명이 있을 때 적용 버튼이 새로고침하지 않는지 확인한 후 저장·업데이트·재로드했다. 두 번째 빌드 버전과 기존 데이터가 함께 유지됐다. 최초 설치의 활성화를 업데이트로 잘못 표시하지 않는지도 검사했다.

**실제 설치 검증:** 임시 Xorg 화면 서버와 `headless:false` Chromium을 사용했다. CDP `PWA.install`로 설치하고 `PWA.getOsAppState`로 조회했다. 브라우저의 앱 표시 사용자 설정을 `standalone`으로 지정한 뒤 `PWA.launch`로 새 앱 창을 열었다. 새 창에서 `matchMedia('(display-mode: standalone)').matches === true`와 기존 할 일 조회를 확인했다. 검증용 설치는 테스트 종료 전에 제거했다. 브라우저 설치 설정과 앱의 manifest 설정을 구분했으며, 화면 없는 모드의 설치 명령 성공만으로 standalone 검증 완료라고 판정하지 않았다.

재현 가능한 스크립트는 `scripts/browser-smoke.mjs`다. 기본은 headless이며, 표시 서버가 있는 환경에서는 `TODO_HEADED=1`과 해당 `DISPLAY`로 실행한다. 해당 브라우저에서 네이티브 설치 검증을 지원하지 않으면 결과 JSON의 `nativeInstall.unverified` 및 원인을 기록하며 설치 완료로 보고하지 않는다.

**미검증:** 실제 사용자 PC의 Windows/Edge, macOS, Firefox/Safari, OS 시작 메뉴/바탕화면 바로가기, 수동 설치 안내 UI의 클릭, 모바일 설치·터치·푸시. PC용 Linux Chromium 자동화 검증과 구분한다. 모바일 CSS 기반 구조는 준비했지만 모바일 최적화 완료를 뜻하지 않는다.

## 코드 리뷰 (테스트 결과와 별개)

직접 실제 변경 코드를 검토했으며 별도 독립 리뷰어나 전체 GROUP 보안 감사는 아니다.

- UI가 IndexedDB를 직접 사용하지 않는지, 업무 규칙과 Repository의 경계, 트랜잭션 commit 후에만 성공 처리하는지 확인했다.
- 완료 시각·관계·종속 삭제·버전 충돌·백업 복원의 참조 무결성을 검토했다. 업무 내용은 일반 문자열로 저장·표시하며 사용자 입력을 HTML로 삽입하지 않는다. 가져온 ID가 DOM 선택자에 사용될 때도 CSS escaping을 적용했다.
- 빠른 메뉴 전환 후 재로드에서 화면 설정이 지연 저장되던 부분을 즉시 트랜잭션 저장으로 수정했다.
- 업무 기록 수정 후 hidden ID와 날짜가 `form.reset()`만으로 올바르게 초기화되지 않던 문제를 명시적 초기화로 수정하고 연속 추가·실패 재시도·개별 삭제로 재검증했다.
- 저장 오류는 모달 안에서도 읽을 수 있도록 표시하고, 기존 성공 알림의 타이머가 새 오류 안내를 숨기지 않게 했다.
- 최초 SW 활성화와 업데이트를 구분했고, 자동 reload가 다른 창의 초안을 지우지 않게 했다. GROUP 루트 SW와 캐시에는 접근하지 않는다.
- 루트의 운영용 `data/` 제외 규칙이 `todo/src/data/` 소스까지 제외하는 것을 발견해, ToDo 내부 `.gitignore`에서 해당 JavaScript 소스만 예외 처리했다. 운영 데이터 제외 규칙은 유지했다.
- 글자 대비와 PC 여백, 버튼/포커스/긴 입력/빈 상태를 실제 캡처로 검토했다.

이 검증 범위에서 알려진 기능 오류는 없다. 브라우저 저장 공간을 사용할 수 없는 경우 저장/업그레이드에 실패할 수 있으며 입력 보존·오류 안내 후 사용자가 저장 공간/다른 탭을 확인해야 한다. 로컬 저장의 장기 보존을 보장하는 서버 백업은 제공하지 않으므로 JSON 백업이 필요하다.

위 최초 검증 당시에는 로컬 구현만 수행했다. 이후 다운로드용 브랜치 게시와 GROUP main의 상태는 DOWNLOAD-VERIFICATION.md에서 구분한다. 운영 배포 및 Codex 환경 저장·게시와는 별개다.
