# ELSOLTEC 그룹웨어 · 초기 개발 버전

Node.js 24 이상과 내장 SQLite를 사용합니다. 외부 패키지 설치 없이 Windows/Linux에서 실행됩니다. React/.NET 대신 현재 개발 환경에서 바로 검증할 수 있는 Node.js로 작성한 초기 구현입니다.

## 실행

저장소 폴더에서 `npm test`로 검증하고 `npm start`로 실행합니다. 기본 포트는 3000이며 루프백 주소에서만 수신합니다. 브라우저로 로컬 서버에 접속합니다. 기본 계정과 비밀번호는 없습니다.

계정 생성은 서버를 실행하는 동일한 DATA_DIR 환경에서 수행합니다. 역할은 employee(직원), manager(실장), ceo(대표이사)입니다. 비밀번호는 12자 이상이어야 합니다. 실장 계정의 회사 내부 아이디는 자유롭게 정할 수 있으며 Microsoft 계정을 사용하지 않습니다.

PowerShell 예시(비밀번호는 명령행 인수에 넣지 않습니다):

```powershell
$secret = Read-Host '초기 비밀번호' -AsSecureString
$env:NEW_USER_PASSWORD = [System.Net.NetworkCredential]::new('', $secret).Password
npm run user:add -- staff01 '직원 이름' employee
Remove-Item Env:NEW_USER_PASSWORD
npm start
```

계정별로 위 절차를 반복하여 실장(manager), 대표이사(ceo)를 생성합니다. 서버가 공개 계정 생성을 제공하지 않으므로 계정 관리는 운영자만 실행합니다.

## 구현한 기능

- 비밀번호 scrypt 해시, 만료 세션, HttpOnly/SameSite 쿠키, 로그인 실패 제한
- 휴가: 연차/오전·오후 반차, 실장→대표이사 승인, 반려, 실장 승인 전 회수, 처리 이력
- 자신의 신청은 직접 승인할 수 없습니다. 실장 본인의 신청을 처리하려면 별도의 실장 역할 계정 또는 결재 규칙 변경이 필요합니다.
- 출퇴근: 서버가 관측한 IP가 220.120.152.40일 때만 등록, 중복 방지, 한국 날짜 기준, 본인 최근 90일 조회
- 메일: HTTPS 카페24 웹메일 링크. 실장 화면에 soltec@elsoltec.com 안내. 그룹웨어는 메일 내용이나 비밀번호를 취급하지 않습니다. 실제 공유 사서함 권한은 카페24에서 제한해야 합니다.

## 설정

- DATA_DIR: SQLite 저장 위치(기본 data/). 개인정보가 포함되므로 접근 권한 제한 및 백업 필요
- HOST / PORT: 기본 127.0.0.1 / 3000
- OFFICE_IP: 기본 220.120.152.40. 개발 테스트에서만 다른 주소로 변경
- PUBLIC_ORIGIN: 배포 시 실제 HTTPS 출처 지정
- NODE_ENV=production: HTTPS 전용 Secure 세션 쿠키 적용

기본적으로 전달 헤더는 신뢰하지 않습니다. TRUSTED_PROXY_IPS에 등록한 직접 연결 IP에 대해서만 X-Real-IP 단일 주소를 허용합니다. 해당 프록시는 반드시 외부 입력 헤더를 실제 접속 IP로 덮어써야 합니다. 누락되거나 복수 주소이면 출퇴근 등록을 차단합니다. 사내 VPN으로 사무실 IP를 공유할 경우 사외 등록을 구별할 수 없으므로 VPN 접속 경로 분리가 필요합니다.

## 운영 전 남은 작업

현재는 내부 검토용이며 인터넷에 직접 공개하지 마세요. HTTPS 배포, 비밀번호 분실 복구, 관리 화면, 근태 수정 승인·관리자 전체 직원 내보내기, 연차 잔여일 계산이 남아 있습니다. 백업·복원은 자동화 테스트로 검증했으며 실제 운영 백업 스케줄과 별도 저장소는 아직 구성하지 않았습니다. PWA 설치 리소스가 제공됩니다. Windows에서의 실제 설치 검증과 별도 실행 파일 패키징은 아직 진행하지 않았습니다. 실제 직원 계정 생성 전에 승인자 계정 및 실장 본인 신청의 결재 규칙을 확정해야 합니다.

## 클라우드 작업 재개

이 작업은 이미 격리된 환경입니다. 기존 체크아웃을 사용하고 사용자가 요청하지 않는 한 Git worktree를 만들지 않습니다. 저장소에서 npm test를 실행하고 필요한 경우 npm start로 서버를 재시작합니다. 라이브 프로세스가 환경 복원 후 유지된다고 가정하지 않습니다.

## 추가된 계정 보안

보안 설정 탭에서 비밀번호를 변경하면 모든 세션이 종료됩니다. 인증 앱(Google Authenticator, Microsoft Authenticator 등)에서 시간 기반 계정을 수동 추가한 뒤 등록 키와 6자리 코드로 확인할 수 있습니다. 등록 키는 비밀번호와 동일하게 보호해야 합니다. 서버와 휴대폰 시간을 동기화하세요. 이미 사용한 코드는 다시 사용할 수 없으므로 다음 코드를 기다려 로그인해야 할 수 있습니다.

운영 모드(NODE_ENV=production)는 미등록 사용자의 업무 API 접근을 차단하며, 로그인 후 보안 설정에서 등록하게 합니다. 로컬 HTTP 개발에서는 Secure 쿠키를 사용할 수 없으므로 기본 개발 모드를 사용하세요. 운영 모드는 반드시 HTTPS와 PUBLIC_ORIGIN 설정 후 사용합니다.

운영자는 본인 확인 후 서버 터미널에서 다음 명령을 실행할 수 있습니다. 직원이나 결재자에게 서버 접근 권한을 부여하지 마세요.

```sh
node server.js user:disable staff01
node server.js user:enable staff01
node server.js user:reset-mfa staff01
```

각 명령은 해당 계정의 모든 세션을 종료합니다. MFA 초기화는 인증 앱 분실 시 사용하며, 사용자가 다시 등록해야 합니다. 기존 SQLite 데이터에는 시작 시 열을 추가하여 마이그레이션하며 업무 기록은 유지됩니다. 인증 앱의 검증 키는 SQLite에 저장되므로 DB와 백업 파일 접근 제한 및 디스크 암호화가 필요합니다. 복구 코드 및 키의 애플리케이션 수준 암호화는 아직 제공하지 않습니다.

## Windows 앱 설치(PWA)

HTTPS 배포 후 Edge 또는 Chrome에서 그룹웨어에 접속하면 설치 조건을 만족할 때 상단에 Windows 앱 설치 버튼이 나타납니다. 브라우저의 앱 설치 메뉴도 사용할 수 있습니다. 시작 메뉴와 작업 표시줄에서 독립된 창으로 실행하는 PWA이며 별도의 .exe 설치 프로그램은 아닙니다. 배포 주소는 아직 정하지 않았으며 실제 Windows 설치는 미검증입니다.

manifest, 192/512 PNG 아이콘, 서비스 워커를 제공합니다. 서비스 워커는 업무 데이터나 로그인 정보를 캐시하지 않습니다. 인터넷이 끊기면 업무 기능을 차단하고 연결 안내를 표시합니다.

## 근태 CSV

출퇴근 탭에서 조회 월을 선택하여 본인의 기록을 다운로드합니다. 한국 시간 기준 출퇴근 시각을 Excel용 UTF-8 CSV로 제공합니다. 다른 직원의 기록은 조회할 수 없습니다. 90일 화면 조회 제한과 달리 월별 내보내기는 저장된 과거 기록도 조회합니다. 운영 모드에서는 이 API에도 MFA 등록 제한이 적용됩니다.

## HTTPS 배포 준비

`deploy/Caddyfile`은 **인터넷 → 같은 서버의 Caddy → 127.0.0.1:3000 Node** 구성용입니다. `deploy/production.env.example`을 참고해 실제 도메인·데이터 경로를 설정하세요. 예시 도메인은 실제 회사 주소가 아닙니다. 환경 파일을 만들었다면 파일 위치를 기록하고 Node와 Caddy에 각각 필요한 변수를 주입해야 합니다. 파일을 작성하는 것만으로 환경변수가 적용되지는 않습니다.

1. 사용할 도메인의 DNS를 배포 서버로 연결합니다.
2. Caddy를 공식 배포판으로 설치하고 80/443 포트만 외부에 개방합니다. Node 3000 포트는 외부에 공개하지 않습니다.
3. Node에 NODE_ENV=production, PUBLIC_ORIGIN(실제 HTTPS 주소), HOST=127.0.0.1, TRUSTED_PROXY_IPS=127.0.0.1과 DATA_DIR을 설정합니다.
4. Caddy에 GROUPWARE_DOMAIN을 설정하고 `caddy validate --config deploy/Caddyfile --adapter caddyfile`로 검사한 뒤 실행합니다. Caddy가 인증서를 발급·갱신합니다.
5. 실제 HTTPS에서 로그인·MFA·사무실 출퇴근·사외 차단·PWA 설치를 검증합니다.

현재 환경에서 Caddy 실행 및 실제 인증서 발급은 검증하지 않았습니다. CDN/로드밸런서가 추가되거나 Caddy가 다른 서버/컨테이너에서 실행되는 경우 이 설정을 그대로 사용하면 안 됩니다. 헤더 정제와 프록시 주소를 실제 네트워크 구조에 맞게 다시 검증해야 합니다. 프록시를 신뢰한다는 것은 해당 호스트에서 전달하는 IP를 신뢰한다는 뜻이므로 같은 서버의 접근도 제한하세요.

## 백업과 복원

저장소 폴더에서 실행합니다. SQLite의 온라인 백업 API로 WAL에 남은 변경사항도 일관된 스냅샷에 포함합니다. 백업 대상은 새 파일이어야 하며 기존 파일을 덮어쓰지 않습니다.

```sh
node scripts/database.js backup data/group.db /private-backups/group-20261027.db
node scripts/database.js restore /private-backups/group-20261027.db /private-data/group-restored
```

경로는 운영체제에 맞게 변경하세요. 복원 대상은 존재하지 않는 새 디렉터리여야 합니다. 복원은 서비스와 다른 경로에 수행하고, 복원본의 기록을 확인한 뒤 기존 서버를 중지하고 DATA_DIR을 복원 디렉터리로 변경하여 재시작합니다. 기존 데이터는 삭제하지 않습니다. 복원본의 모든 로그인 세션은 제거되어 재로그인이 필요합니다.

백업에는 비밀번호 해시·인증 앱 키·개인정보가 들어 있으므로 암호화된 별도 저장소에 제한된 권한으로 보관하세요. 하루 1회 자동 백업과 정기 복원 훈련을 권장하지만, 이 저장소가 외부 저장소나 자동 스케줄을 생성하지는 않습니다. 운영체제 ACL도 확인하세요. 실제 원본 데이터 경로가 다르면 DATA_DIR/group.db를 사용해야 합니다.
