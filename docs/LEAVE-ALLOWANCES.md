# 사용자별 휴가 부여와 사용 일수 관리

## 최초 설정

Admin으로 로그인한 뒤 **사용자 관리 → 휴가 관리**를 엽니다. 연도를 선택하고 사용자 이름 또는 **수정**을 눌러 일수를 저장합니다. 입사일과 퇴사일도 이 화면에서 관리합니다. 권한은 Admin에게만 있으며 이사·대표 역할만으로는 다른 사용자의 휴가를 부여하거나 조회할 수 없습니다.

연차·정기휴가·보건휴가·포상휴가를 별도 관리합니다. 기본 부여, 연차 이월·공제, 기존 사용 일수는 0.5일 단위입니다. 부여 값은 추가 지급분이 아닌 **해당 연도의 누적 총량**입니다. 변경 사유와 변경 전후 수치는 **부여 이력**에 남습니다. 조회 표는 엑셀로 다운로드할 수 있습니다. 비활성 사용자도 포함하여 조회할 수 있습니다.

**처음에는 모든 사용자의 부여 일수가 0일입니다.** 입사일이나 근속연수로 자동 부여하지 않습니다. Admin이 실제 부여 일수를 설정해야 새 휴가를 신청할 수 있습니다. 연도는 1월 1일~12월 31일 기준입니다. 다음 해 이월 일수도 Admin이 직접 설정합니다.

## 집계 기준

| 항목 | 계산 |
| --- | --- |
| 전체 부여 | 기본 부여 + 이월 − 공제 |
| 사용 | 시스템 도입 전 기존 사용 + 이사 승인/최종 승인 문서의 차감 일수 |
| 결재 대기 | 이사 승인을 기다리는 문서의 예약 일수 |
| 신청 가능 | 전체 부여 − 사용 − 결재 대기 |

**기존 사용**에는 시스템에 이미 등록된 휴가를 중복 입력하지 않습니다. 이사 승인된 문서는 자동 집계됩니다. 연차의 오전/오후 반차는 각각 0.5일로 처리하며, 정기·보건·포상휴가는 각각의 부여량에서 차감합니다. 부여량을 승인·대기·기존 사용 합계보다 작게 저장할 수 없습니다.

기안 상신 시 일수를 예약합니다. 이사 승인 시 예약에서 사용으로 전환하며 대표 승인 때 다시 차감하지 않습니다. 반려·회수 또는 허용된 문서 삭제 시 해당 사용/예약 일수가 해제됩니다. 휴가 유형별 일수가 부족하면 상신 버튼을 막고 서버도 요청을 거절합니다. 동시에 여러 창에서 신청하더라도 같은 잔여 일수를 중복 사용할 수 없습니다. 다른 유형에 남은 일수는 해당 유형으로 신청할 수 있습니다.

## 평일과 공휴일

사용자가 지정한 기준에 따라 **토요일·일요일·공휴일·회사 휴일을 제외한 평일만** 차감합니다. 한국 공휴일 규칙과 대체공휴일을 기본 반영하며 설·추석 연휴, 근로자의 날, 2026년 전국동시지방선거일도 제외합니다.

**공휴일·회사 휴일**에서 해당 연도의 기본 휴일을 확인하고 창립기념일 등 회사 휴일이나 추가 지정된 임시공휴일을 등록할 수 있습니다. 기본 휴일 규칙은 설치된 `date-holidays` 데이터로 계산하며 정부 서비스의 실시간 지정 공지를 자동 수신하지는 않습니다. 새 임시공휴일은 Admin이 추가하세요. Admin이 등록한 휴일은 삭제할 수 있습니다.

회사 휴일 추가·삭제는 **이후 새 신청**에 적용합니다. 이미 상신한 문서의 차감 일수는 당시 계산값으로 보존하여 사용 내역이 사후에 바뀌지 않게 합니다. 새 정책으로 다시 계산해야 하는 진행 중 문서는 기존 삭제/회수 권한 범위에서 처리한 뒤 다시 신청하세요.

예: 금요일부터 다음 주 화요일까지 신청하면 평일 3일이며, 월요일이 공휴일이면 2일입니다. 주말·휴일만 있는 기간은 신청할 수 없습니다. 반차는 근무일 하루만 선택합니다. 연도를 넘기는 기간은 각 연도에 나누어 계산하고, 두 연도 모두 잔여량이 있어야 상신합니다. 신청 기간은 최대 366일, 관리 연도 범위는 2000~2050년입니다.

## 기존 기록과 접근 권한

기존 휴가 문서는 새 버전 최초 실행 시 평일 기준 차감량을 계산해 한 번만 저장합니다. 기존 승인 문서는 사용, 진행 중 문서는 결재 대기로 집계하고 문서·서명·결재 상태는 보존합니다. 기존 자료에 부여 일수 정보는 없으므로 Admin이 실제 부여량을 먼저 입력해야 합니다. 부족한 경우 신규 상신과 추가 승인에 잔여량 확인 안내가 표시됩니다.

일반 사용자는 휴가 신청서에서 본인의 부여·사용·예약·신청 가능 일수를 봅니다. 다른 사용자 잔여량, 휴가 부여 이력, 관리자 엑셀에는 접근할 수 없습니다. 사용자 영구 삭제 시 휴가 부여량·프로필·차감량·관련 부여 이력도 함께 삭제합니다.

## 설치와 검증

기존 서버 종료 → 새 프로젝트를 별도 폴더에 압축 해제 → 기존 **data 폴더 전체 복사** → **START-LOCAL.cmd** 실행 → Edge **Ctrl+F5** 순서로 업데이트합니다. 런처가 새 공휴일 패키지를 포함해 설치 여부를 확인합니다. 직접 실행한다면 먼저 `npm.cmd ci`를 실행하세요. `node_modules`를 복사할 필요는 없습니다.

`npm test` 32개 통과. 전용 정책 테스트는 초기 부여 0일, Admin 권한, 반차·공휴일·회사 휴일 제외, 잔여 부족, 동시 상신 경쟁, 이사 승인 및 반려/회수/삭제 복원, 유형별·연도별 집계, 기간 휴가, 기존 자료 이전, 수정 충돌, 엑셀, 사용자 영구 삭제와 백업 복원을 검증합니다. 기존 업무 테스트는 `test-support/server.js`에서 테스트 계정에만 명시적인 테스트용 부여량을 넣으며 운영 계정에는 적용되지 않습니다.

Chromium의 `scripts/leave-management-smoke.mjs`에서 하위 메뉴와 권한, 부여/변경 이력, 엑셀, 회사 휴일 추가, 직원 잔여량 표시와 소진 차단, 이사 승인 집계, 모바일 화면을 확인했습니다. 실제 Windows/Edge 직접 실행 검증과는 구분합니다.
