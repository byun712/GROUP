## 구현과 유지할 규칙

- 기본 공정별 진척률 카드의 제목 오른쪽에 36px 확장 버튼을 추가했다. 제목 행 높이·기본 카드 위치/크기는 유지한다. 마우스와 키보드 초점에서 `크게 보기` 설명을 제공한다.
- 확장 화면은 프로젝트 본문 폭의 흰 영역으로 겹쳐 표시한다. 원래 보드를 이동·삭제하지 않으며 화면 전체를 어둡게 하는 배경, 새 창/탭, 브라우저 전체화면을 사용하지 않는다. 메뉴와 본문 상단의 보고서/관리 버튼은 그대로 둔다.
- 접기 버튼 또는 Esc로 복귀한다. 기존 공정 상세 창이 열린 경우 첫 Esc는 상세 창을 닫고 다음 Esc가 확장을 접는다. 원래 버튼 초점, 페이지 스크롤, 축소 그래프 가로 스크롤을 복원한다. 가려진 보드는 `inert`와 `aria-hidden`으로 조작을 막고 이전 속성값으로 복원한다. 메뉴 이동·프로젝트 전환·로그인 갱신 시 정리한다. 이벤트 리스너는 한 번만 등록한다.
- 제목·프로젝트명·전체/표시 공정 수, 전체/진행 중/완료 필터, 이름 검색을 제공한다. 상태는 서버의 `todo/doing/blocked/done`을 그대로 사용하며 전체에는 예정과 보류도 포함한다. 공정 없음과 검색 결과 없음은 구분한다.
- 축소·확장은 동일한 렌더러와 프로젝트 데이터, 공정 ID 기반 색상을 사용한다. 0~100% 축, 0% 숫자, 100% 상단 여백, 공정 상세 연결을 유지한다. 확장 막대 폭은 48px, 공정별 슬롯은 120~168px로 유지하고 많은 공정은 내부 가로 스크롤한다. 이름은 최대 네 줄과 전체 이름 tooltip/접근성 이름을 제공한다. 방향키·Home/End로 이동할 수 있다.
- 하단은 항상 **프로젝트 전체 기준**의 진척률, 완료 공정 수/전체 공정 수, 최저 공정과 값이다. 동률이면 대표 공정과 동률 수를 표시하고 전체 동률 이름은 설명으로 제공한다. 검색·필터는 데이터나 프로젝트 평균·엑셀 범위에 영향을 주지 않는다.

`public/project-comparison.js`는 확장 상태·위치·포커스·필터 정리를 담당한다. `public/business.js`의 공통 `taskComparisonChart`가 축소/확장을 그린다. 새 스타일은 확장 영역과 관련 버튼에 한정한다. `server.js`의 변경은 새 정적 스크립트 경로 허용뿐이며 새 API·권한·DB 변경은 없다.

## 프로젝트 XLSX

`프로젝트 보고서` 시트의 공정 요약 열(순번, 공정명, 시작/종료일, 담당자/참여자, 전체/완료 일수, 숫자 진척률, 상태)을 유지하고 각 공정 **바로 아래**에 전체 수행 기록을 추가한다.

- 상위 행은 굵은 글꼴·옅은 배경, 하위는 `↳ 공정 순번`과 들여쓴 보조 본문이다. 하위 B:F는 수행 내용, G:H는 수행일자, I:J는 작성자다. 기록 작성일시(KST)·공정 ID·기록 ID는 본문 셀 메모에서 확인하고 기존 별도 수행 내역 시트에도 표시한다.
- `work` 및 실제 사용자 내용이 있는 `legacy`만 포함한다. 공정 등록/정보 수정/완료 체크의 알려진 자동 기록, 빈 기록, 다른 공정·프로젝트의 기록은 포함하지 않는다. 일정 변경은 기존 별도 시트에 보존한다.
- 공정 안에서 수행일자 → 작성일시 → 기록 ID 순으로 안정적으로 정렬한다. 수행일자가 없는 이전 기록은 `미기록`으로 표시하며 날짜를 추측하지 않는다. 기록 없는 공정은 요약 행만 있다.
- 전체 프로젝트·전체 기간을 서버에서 조회한다. 화면의 두 카드·조회 월·스크롤·확장·검색/상태 필터는 다운로드 조건이 아니다. 기존 활성 로그인 직원의 공동 프로젝트 조회 정책과 인증 게이트를 유지한다. 개인 일정·다른 프로젝트를 포함하지 않는다.
- 긴 본문은 최대 네 시각적 줄 단위로 여러 행에 나누며 순서대로 합치면 원문이 복원된다. CRLF/LF, 빈 줄, 탭, 한글/결합 문자/이모지, `_x0041_` 같은 문자열을 OOXML 안전 문자열로 보존한다. `=`로 시작해도 수식이 되지 않는다.
- 메인 계층형 영역은 일반 자동 필터를 제거해 공정과 기록이 흩어지지 않도록 했다. `공정 수행 내역`과 `일정 변경 내역` 평면 시트는 필터를 유지한다. 모든 하위 행은 기본으로 보인다.
- A4 가로, 가로 한 페이지/세로 자동, 반복 표 헤더·고정 헤더·인쇄 영역·여백·숫자 형식을 유지한다. 본문 행은 최대 74pt로 제한한다. 공정 요약과 첫 수행 행이 한 페이지에 들어갈 크기이면 그 사이에서 수동 페이지를 나누지 않는다. 아주 긴 공정/기록 묶음은 다음 페이지로 이어진다.

## 코드 리뷰와 수정

실제 diff를 데이터 흐름, 권한, 원문 보존, 상태 정리, 접근성, CSS 범위 기준으로 직접 리뷰했다. 독립된 별도 리뷰어나 전체 저장소 보안 감사는 아니다.

1. 축소·확장 렌더러를 공유해 값/색상 차이를 방지했다. 필터는 복사 목록에만 적용하고 전체 요약과 다운로드는 원본 프로젝트를 참조한다.
2. 가려진 보드의 기존 inert/aria 속성 및 스크롤을 저장·복원한다. 공정 상세 창의 Esc와 확장 Esc가 충돌하지 않게 처리했다. 새 프로젝트나 메뉴 이동 시 예전 확장 화면이 남지 않게 정리했다.
3. 수행 기록을 동일한 정렬/선별 함수로 메인·별도 시트에 공급한다. 사용자 내용과 시스템 기록을 구분하고 하위 행을 공정 수/진척률로 다시 집계하지 않는다.
4. 재읽기 테스트에서 발견한 CRLF 정규화와 OOXML 이스케이프 문자열 손상을 안전한 문자열 인코딩으로 수정했다. 공백이 붙은 이전 자동 기록도 제외하도록 보완했다. 수정 후 원문 일치·API·전체 회귀 테스트를 재실행했다.
5. 기존 label의 기본 flex 스타일과 흐린 요약 글자색이 확장 화면에 적용되는 부분을 범위가 제한된 스타일로 수정하고 세 폭을 다시 촬영했다.

## 직접 확인하지 못한 범위

요청 기능의 알려진 미완료 구현은 없다. **Microsoft Excel/LibreOffice에서 직접 PDF로 렌더링하거나 실물 인쇄하지 않았다.** 인쇄 설정·행 높이·명시적 페이지 나눔·부모/첫 기록 연결은 XLSX 및 OOXML로 검사했으나 실제 글꼴/프린터의 출력 결과와 동일하다고 보장하지 않는다. Windows/Edge, Safari/Firefox, 실제 모바일 터치 기기는 직접 검증하지 않았다. 운영 배포·메일 서버·데이터 복원·환경 게시는 이번 작업 범위 밖이다.

최종 SHA와 원격 main 일치는 push 후 완료 응답에서 제공한다. 새 작업은 최신 main을 fetch하고 [HANDOFF.md](HANDOFF.md), [NEW-CHAT-SETUP.md](NEW-CHAT-SETUP.md)를 먼저 읽는다. 과거 실행 환경 ID를 재사용하거나 데이터가 안 보인다고 운영 데이터를 초기화하지 않는다.
