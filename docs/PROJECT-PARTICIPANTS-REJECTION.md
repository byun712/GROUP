# 프로젝트·공정 참여자와 승인 후 반려

## 담당자와 참여자

프로젝트 등록/수정에서 **프로젝트 담당자** 한 명과 **참여자** 여러 명을 선택합니다. 이름·부서·직급으로 참여자를 검색할 수 있습니다. 담당자는 참여자로 중복 선택하지 않습니다. 최초 등록자는 보존하며 기존 프로젝트의 초기 담당자는 기존 등록자로 설정됩니다.

공정 등록/수정에서도 **담당자**와 **참여자**를 별도로 선택합니다. 공정 참여자는 프로젝트 참여자와 독립적으로 지정할 수 있습니다. 프로젝트 상세, 공정 달력의 설명, 대표 공정 및 수행 내역 상세에서 참여자를 확인할 수 있습니다. 참여자만 수정해도 기존 완료 일수·공정률·수행 내용은 보존됩니다.

기존 비활성 참여자/담당자는 수정 화면에 표시하여 유지하거나 교체할 수 있습니다. 신규 참여자는 활성 사용자 중에서 선택합니다. 다른 사용자가 동시에 수정한 이전 버전은 저장을 거절하고 다시 조회하도록 안내합니다. 기존의 모든 활성 사용자 공동 편집 권한과 Admin 전용 공정 삭제 권한은 유지됩니다.

공정 삭제 시 참여자 연결도 함께 삭제합니다. 사용자 영구 삭제 시 해당 참여자 연결과 연결된 변경 기록을 제거합니다. 삭제 사용자가 다른 사람이 등록한 프로젝트의 담당자였다면 담당자를 원래 등록자로 돌리고 프로젝트는 보존합니다. 참여자 정보는 SQLite 백업에 포함됩니다.

## 이사 승인 후 반려

전자결재와 업무보고 문서를 열면 **직접 승인했던 이사**에게 **승인 후 반려** 버튼이 표시됩니다. 대표이사가 아직 승인/반려하지 않은 문서에서만 가능합니다. 버튼을 누르고 확인한 뒤 저장하면 반려로 변경됩니다. 다른 이사나 Admin 권한만으로는 기존 이사의 승인을 뒤집을 수 없습니다.

대상은 휴가·지출결의서·기타 기안과 교육계획서·교육보고서·회의록·일일업무일지입니다. 이미 승인했던 문서는 결재함의 전체/진행 목록 또는 문서 상세에서 다시 열 수 있습니다.

기존 이사 승인 이력은 유지하고 새 반려 이력과 처리 날짜·서명/도장을 추가합니다. 문서의 이사 결재란과 엑셀에는 가장 최근의 반려 결과를 표시합니다. 이사 반려를 대표 처리로 간주하지 않으므로 대표 처리 전 작성자/Admin의 문서 삭제 정책도 적용됩니다.

휴가를 반려하면 일정관리·근태 달력에서 제외하고 사용 일수를 복원합니다. 대표 최종 승인 전 지출에는 회계 전표가 생성되지 않습니다. 대표의 처리가 먼저 완료되면 뒤늦은 이사 반려 요청은 거절합니다.

## 업데이트와 검증

기존 서버 종료 → 새 폴더에 압축 해제 → 기존 `data` 폴더 전체 복사 → `START-LOCAL.cmd` 실행 → Edge Ctrl+F5 순서로 적용합니다. 새 외부 패키지는 추가하지 않았습니다. 기존 자료에 참여자 연결 테이블·담당자·결재 단계 열을 추가하며 기존 공정과 문서·결재 이력은 보존합니다.

`npm test` 33개 통과. 새 통합 테스트는 프로젝트/공정 담당자와 참여자 생성·수정, 중복/유효 사용자/비활성 사용자 검증, 수정 충돌, 백업·사용자/공정 삭제 정리, 4종 문서 계열의 승인 후 반려와 권한, 대표 처리 후 차단, 이력·서명·엑셀·휴가 일수 복원, 재실행 후 결재 단계 유지와 문서 삭제 권한을 확인합니다.

Chromium의 `scripts/project-members-smoke.mjs`와 `scripts/business-smoke.mjs`에서 참여자 선택·담당자 교체·저장·모바일 화면, 전자결재/업무보고의 승인 후 반려, 최신 반려 표시와 기존 업무 동작을 검증했습니다. 실제 Windows/Edge 직접 실행 검증과는 구분합니다.
