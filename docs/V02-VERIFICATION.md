브라우저 테스트는 README의 Playwright/Chromium 환경 변수 설정 후 실행했다. [기존 회귀 결과](screenshots/v02/regression-verification.json), [0.2 검증 결과](screenshots/v02/workspace-verification.json), [예시 백업](screenshots/v02/v2-example-backup.json)에 실제 결과를 보관했다.

추가 검증은 다음을 확인했다.

- 실제 버전 1 IndexedDB를 먼저 만든 뒤 버전 2 앱을 실행. 기존 모든 필드의 ID/본문/날짜/시각/참조 동일 비교.
- 목록 → 보드 → 캘린더의 상태 일치 및 마감일 변경에 따른 날짜 이동. 할 일 복제 없음.
- HTML/script/이벤트 속성의 텍스트 표시, javascript 링크 차단, 정상 링크·마크다운 미리보기.
- 넓게/좁게/보기 전환 중 설명 초안 보존. 하위 입력을 쓰면서 다른 하위의 완료를 변경해도 입력 보존.
- 실제 IndexedDB put에 QuotaExceededError를 주입. 하위 입력 보존, 저장 성공으로 오인하지 않음, 재시도 성공.
- 부모 프로젝트/공정 변경 시 하위 동시 변경. 단위 테스트로 중첩/순환/잘못된 참조 거부, 부모 삭제 시 해당 하위·로그만 삭제.
- 템플릿 부모/하위 ID 신규 생성, 완료 시각·수행 기록 미복제. 빈 날짜 또는 새 지정 날짜 적용.
- 8가지 조건을 함께 적용한 세 보기의 동일 결과, 저장한 보기의 재접속 유지, 원본 상태 변경에 따른 결과 제외.
- 프로젝트 전체 완료율의 필터 독립성 및 하위 중복 제외.
- 같은 날짜의 많은 업무를 스크롤/키보드로 열기, 날짜 미지정, 날짜 클릭 등록.
- 상세 열기/닫기 후 목록 스크롤·키보드 포커스 복귀.
- 새 모델을 포함하는 JSON 2 내보내기. 단위 테스트로 JSON 1 변환 및 JSON 2 전체 왕복 검증.
- 취소하고 닫은 모달의 과거 입력 상태가 PWA 업데이트를 잘못 차단하지 않음.

## PWA 검증

기존 `/todo/` manifest ID/start_url/scope 및 정적 자산 전용 SW를 유지했다. 신규 JS 파일도 콘텐츠 해시 기반 빌드 캐시에 포함한다. 네트워크 차단 후 새 보드/캘린더 열기, 상태/설명 수정, 재로드 후 값과 저장한 보기 유지가 통과했다. 기존 회귀에서는 새 SW 버전 대기·미저장 초안으로 업데이트 차단·저장 후 명시적 적용·기존 DB 보존을 재검증했다. 개발 모드에는 SW가 없고 다른 GROUP 경로나 API를 캐시하지 않는다.

Linux Chromium 자동화에서 CDP 설치, 앱 상태 조회, standalone 사용자 표시 설정, 앱 창 재실행, standalone 매체 조건 및 기존 데이터 표시를 확인했다. 수동 OS 설치나 Windows/Edge 실행 확인으로 확대하지 않는다.

## 데이터 이전

- DB 이름은 `group-todo-local` 그대로, 버전만 1 → 2다.
- 기존 5개 저장소는 보존한다. `savedViews`, `templates`, `profiles`를 추가한다.
- 기존 Task에 `parentId: null`, `assigneeId: null`, `tags: []`를 추가한다. 수정 시각·버전·원문은 마이그레이션 자체로 바꾸지 않는다.
- IDB versionchange 트랜잭션 안에서 수행한다. 실패 시 기존 DB를 지우지 않으며 다른 탭으로 업그레이드가 차단되면 안내한다.
- JSON 형식 2는 새 모델을 모두 포함한다. 형식 1을 읽으면 빈 새 저장소와 Task 기본값을 추가하여 검증 후 원자적으로 복원한다.
- 원래 주소·포트·브라우저 프로필을 계속 사용하고 먼저 JSON 백업을 보관한다. 구버전 앱으로 새 DB를 열어 버전 오류가 나면 초기화하지 말고 새 앱을 사용한다.

## 코드 리뷰 결과 — 테스트와 별도

별도 독립 리뷰어가 아닌 실제 변경 코드의 자체 리뷰다. UI → Service → Repository → IndexedDB 경계, 스키마 이전, 부모·자식 관계, 집계/필터 분리, 복원 검증, 태그/마크다운 출력, 서비스 워커 범위를 확인했다.

발견하여 수정한 사항:

1. 상세 닫기 후 보드/달력 항목의 포커스가 돌아오지 않던 경로를 보완했다. 목록 재렌더링 시 조작 중인 속성의 포커스와 스크롤도 보존한다.
2. 다른 하위 작업을 완료하면서 새 하위 입력이 지워질 수 있어, 입력과 dirty 상태를 재렌더링 사이에 유지한다.
3. 닫고 버린 대화상자의 dirty 표시가 전체 미저장 판정에 남던 문제를 고쳤다. 닫힌 대화상자는 업데이트 차단 대상에서 제외한다.
4. 프로젝트 그룹은 이름이 같은 서로 다른 프로젝트를 합치지 않도록 ID로 묶는다.
5. 데이터 필터로 완료 행이 즉시 사라지는 정상 동작을 브라우저 테스트가 체크박스 잔존으로 기다리던 부분을, 클릭 후 행 제외와 DB 완료 시각을 검증하도록 수정했다.
6. 긴 보드 제목은 세 줄로 제한하고 전체 이름은 title 설명과 상세로 제공한다.

## 제한 및 다음 단계

- Windows `.cmd` 직접 실행, 실제 사용자 PC의 Edge/macOS/Safari, 수동 OS 설치 UI, 모바일 설치·터치·최적화는 직접 확인하지 않았다.
- 실제 사용자 DB는 읽지 않았다. 보존은 별도 버전 1 복제 데이터에서 검증했다.
- 로컬 프로필·담당자 필터는 권한이 아니다. 로그인, 팀원 초대, 공유 권한, 사용자 간 동시 편집/댓글, @멘션, 서버 첨부, 자동 반복, 푸시, GROUP API 동기화는 미구현이다.
- Markdown은 명시된 부분 문법만 지원한다. 브라우저 용량이나 프로필 삭제에 대비한 서버 백업은 없으므로 JSON 백업이 필요하다.
- 후속은 인증/권한 확인 → 실제 프로젝트·공정/업무 API 계약 → DTO 매핑 → 원격 Repository/원자적 명령 → 충돌·삭제·동기화 → 기존 로컬 데이터 이전 → 협업/모바일 순서다. 구체적인 연결 지점은 [GROUP-INTEGRATION.md](GROUP-INTEGRATION.md)에 있다.
