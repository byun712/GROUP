# 워크스페이스 v2 구현·검증 기록

기준 커밋: `64a549b97909a050043525de2bd795b20626d08b`. 시작 시 작업 트리는 깨끗했으며 원격 main을 fetch하여 같은 커밋임을 확인했습니다. 운영 데이터와 서버의 권한·결재·근태·진척률 계산 코드는 변경하지 않았습니다.

## 요구사항별 반영

1. **상단 여백**: 공통 레이아웃 변수로 데스크톱 24px, 모바일 16px 적용. 11개 메뉴에서 상단 메뉴 아래 간격을 실제 DOM 좌표로 비교했습니다. 큰 메뉴명·오늘 날짜를 다시 넣지 않고 기존 활성 메뉴 색상을 유지했습니다.
2. **홈 캘린더**: 실제 상단 메뉴·요약·여백 높이를 측정하여 남은 화면 높이에 맞춥니다. 4·5·6주를 균등 배분하며 모바일에서는 읽기 쉬운 셀 높이와 페이지 스크롤을 사용합니다. 날짜는 고정, 일정 목록만 내부 스크롤, 일정은 한 줄입니다. 일정 상세/편집과 승인 휴가 상세를 버튼으로 열 수 있습니다.
3. **좌측 서식**: 전자결재 12개, 업무보고 4개의 기존 서식을 부모 메뉴 바로 아래에 표시합니다. 중간 신규기안/신규보고와 서식 flyout 제거. 펼침 표시, 선택 서식/상위 메뉴 활성 상태, Tab·방향키·Home·End·Escape 조작을 제공합니다. 작성 화면에서 부모를 누르면 문서 목록으로 돌아오며 목록에서는 접기/펼치기로 동작합니다. 본문 양식 카드도 유지했습니다.
4. **프로젝트 세 영역**: 상단 패널 362→322px. 도넛·가로 비교 그래프·수행 내역의 기준선을 맞췄습니다. 공정별 고유 ID 기반 색상을 도넛과 막대에 공유합니다. 기존 전체 진척률은 서버의 공정별 진척률을 단순 평균하고 반올림한 값입니다. 따라서 도넛은 공정마다 같은 각도를 배정하고 각 구간만 해당 진척률만큼 채웁니다. 중앙 숫자는 기존 반올림 결과를 사용합니다. 완료 공정 개수 비율로 계산하지 않습니다.
5. **수행 내역**: 목록 244px, 기본 카드 116px 두 개와 간격 12px. 세 번째부터 내부 스크롤. 긴 이름/사람 정보는 잘라내지 않고 줄바꿈하므로 긴 카드는 높이가 늘어날 수 있지만 바깥 패널은 고정됩니다. 생성 시각 내림차순+ID 내림차순, 새 등록 시 상단 이동, 같은 데이터 갱신 시 스크롤 보존을 유지했습니다.
6. **프로젝트 선택 카드**: 색상/이름/상태, 기관, 기간의 세 정보 행. 반복 진척률·공정 수·장식 막대 제거. 기본 높이 100px, 최소 열 너비 320px, 긴 내용은 줄바꿈하며 모바일은 한 열입니다.
7. **프로젝트 정보 바**: 이름, 기관/기간, 등록자/담당자/참여자, 상태 선택/저장을 데스크톱 가로 배치. 작은 화면에서 줄바꿈. 설명, 기존 변경 이력 접힘 항목과 상태/수정 기능 유지.
8. **일정관리 주간 목록**: 홈과 동일한 날짜 렌더러 사용. 기본 접힘, 펼침 상태는 데이터 갱신 시 유지. 한국 날짜의 일요일~토요일, 오늘 주/다른 달 첫날 주/선택 날짜 주 및 이전·다음·이번 주 지원. 선택 주와 겹치는 월을 기존 권한 필터 API로 조회하여 ID로 중복 제거합니다. 월·연도 경계와 여러 날 일정/승인 휴가를 포함하고 화면 필터를 동일 적용합니다.

## 코드 리뷰 결과와 수정

- **조회 중 주간 데이터 혼합**: 새 주의 날짜 범위 아래에 이전 목록이 잠깐 남는 문제를 로딩 상태로 교체했습니다. 로딩 중 필터가 이전 스냅샷을 다시 렌더하지 않도록 월/주 키를 검증합니다. 오래된 요청은 현재 요청 결과를 덮어쓸 수 없습니다.
- **상위 메뉴 이동 회귀**: 서식 작성 화면에서도 부모 클릭을 접기만 하던 경로를 수정해 문서 목록으로 이동하게 했습니다. 실제 목록 화면에서만 클릭으로 접기/펼치기를 합니다.
- **기존 이벤트 보존**: 최종 차이 검토에서 서식 메뉴 교체 범위에 기존 기안 제출 이벤트와 사용자 하위 메뉴 키보드/스크롤 처리가 함께 제거된 것을 발견해 원래 처리를 복구했습니다. 브라우저에서 실제 기안 상신과 사용자 메뉴 키보드 조작을 검증에 추가했습니다.
- **월 경계 정렬**: 여러 월의 결과를 합친 뒤 기존 API와 같은 시작일·시각·ID 순서로 다시 정렬해 이전 달에서 끝나는 주간 일정도 올바른 위치에 표시합니다.
- **긴 내용**: 프로젝트 요약은 패널 안에서 스크롤하고 공정 이름·메타 정보는 줄바꿈하도록 보완했습니다. 제목 버튼의 전체 텍스트와 기존 상세 화면을 유지했습니다.
- **진척률/색상 검토**: 저장 산식은 그대로이며 공정별 동일 가중치를 시각화합니다. 공정 ID 기반 색상은 조회/선택 순서에 의존하지 않습니다. 모든 정렬은 복사한 배열에서 실행합니다.
- **권한/데이터 검토**: 기존 일정 조회 API의 권한 필터와 수정/삭제 가능 플래그를 그대로 사용합니다. 승인 휴가는 기존 API의 최소 공개 정보만 표시합니다. 결재·근태 API와 등록 대상은 변경하지 않았습니다.
- 의도적으로 바뀐 이전 타임라인·2.5개 노출·떠 있는 서식 메뉴 테스트는 새 요구사항으로 갱신했습니다. 기존 기능 검증은 유지했습니다. 최종 검증에서 미해결 기능 회귀는 발견하지 못했습니다.

## 확인 범위와 제한

- Chromium과 모바일 폭 에뮬레이션으로 검증했습니다. 실제 iOS/Safari/Firefox는 확인하지 않았습니다.
- 매우 낮은 창에서는 날짜와 조작 요소의 가독성을 위해 홈 달력 최소 높이 220px를 유지하므로 페이지 스크롤이 생길 수 있습니다. 요청한 두 데스크톱 해상도에서는 화면 안에 들어갑니다.
- 생성 이력이 없는 과거 공정은 기존 정책대로 ID를 보조 기준으로 사용합니다. 임의의 생성 시각을 만들지 않습니다.
- 스크린샷은 검증용 가상 데이터입니다.
