# 프로젝트 워크보드 및 문서 양식 UI 변경 검증

## 변경 1~5

1. 선택 프로젝트만 도넛·숫자·요약에 표시. 기존 서버 공정 진척률의 반올림 산술평균을 공통 함수로 재사용하고 완료 공정 개수 비율과 구분. 0/빈 상태 처리, 선택 테두리/aria-pressed, 오래된 조회 응답 무시.
2. 기존 공정 수행 내역을 상단 오른쪽으로 이동. 선택 프로젝트 전체 공정을 표시하며 280px 내부 스크롤, 모바일 세로 배치. 제목·퍼센트/보조 정보/막대 순서. 기존 상세와 변경 사유, 하단 프로젝트 기본 정보·담당자·참여자·이력·수정/등록 기능 보존.
3. 캘린더 상단의 전체 진척률 텍스트/막대 제거. 안내를 단축하고 월 이동·완료 체크·상세 기능 유지.
4. 두 메뉴에 공통 document-filters 적용. 흰 컨테이너와 입력 배경, 40px 입력 높이, 14px 간격, 라벨·하단 정렬. 기존 검색 실행 방식과 필터/페이지 이벤트 보존.
5. 카드 내 결재 과정 설명만 제거. 글자 12px 유지, 패딩 축소와 세로 중앙 정렬. 데스크톱 6열/모바일 2열 유지. 실제 결재 흐름과 화면의 결재 안내는 유지.

## 실제 높이 측정

수정 전 기준 커밋: `0d3a80f0c0838d83dab0246b0ff90582fadd1f4d`.
Chromium에서 폰트 로딩 완료 후 `getBoundingClientRect().height` 측정.

| 뷰포트 | 전자결재 12개 카드 전 → 후 | 업무보고 4개 카드 전 → 후 |
| --- | --- | --- |
| 1366×768 | 56.09375 → 37.390625px | 56.09375 → 37.390625px |
| 1920×1080 | 56.09375 → 37.390625px | 56.09375 → 37.390625px |
| 390×844 | 56.09375 → 37.390625px | 56.09375 → 37.390625px |

모두 원래 높이의 약 66.66%. CSS 최소 높이는 37.4px이며 브라우저 소수점 양자화로 실제 값은 위와 같습니다. 고정 높이로 텍스트를 자르지 않고 긴 이름에는 높이 증가를 허용합니다.

## 자체 코드 리뷰 및 수정

- 전체 프로젝트를 합산하던 도넛을 선택 프로젝트로 한정. 중앙 숫자·원형·카드가 동일 계산 함수를 사용하도록 정리.
- 공정 목록을 이동하면서 기존 DOM ID와 상세 콜백을 재사용. 빈 프로젝트 전환 시 이전 목록을 비우며 조회 월에 의해 상단 목록이 누락되지 않도록 분리.
- 중첩 프로젝트 조회의 오래된 응답이 새 상태를 덮어쓸 수 있던 부분에 요청 순서 검사를 추가하고 역순 응답 테스트.
- 모바일 긴 공정명은 목록에서 간결하게 유지하고 보조 정보의 기존 nowrap을 해제해 두 줄로 표시. 상세에는 전체 내용 보존.
- 제거된 진척률 막대를 가리키던 테스트를 새 도넛 값 검사로 변경. 프로젝트 색상 표시가 두 곳에 생겨 기존 테스트 선택자 범위를 카드로 한정. 기존 사용자 메뉴의 두 번째 클릭 동작에 맞게 오래된 테스트 갱신.
- 서버 저장/계산/권한/결재 코드 변경 없음. 최종 리뷰에서 미해결 데이터 혼합, 잘못된 진척률, 권한 누락, 기능 회귀는 발견되지 않음.

## 제한

Chromium과 390px 뷰포트 에뮬레이션 검증이며 실제 모바일 기기·Safari·Firefox는 확인하지 않았습니다. 문서 목록의 많은 열은 모바일에서 기존 가로 스크롤을 유지합니다.
