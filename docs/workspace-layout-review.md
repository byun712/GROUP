# 프로젝트·근태·공통 메뉴 UI 검증

## 반영 내용

1. 프로젝트 상단은 같은 362px 높이의 세 패널과 16px 간격으로 정렬. 프로젝트 선택 카드는 145px, 공정 수행 카드는 104px로 역할별 규격 통일. 모바일은 세로 배치.
2. 선택 프로젝트의 기존 평균 진척률 도넛과 프로젝트명/기간/상태/완료 수를 표시. 공정에는 선후행 데이터가 없어 시작일 기준 타임라인을 사용하고 연결선이 의존 관계가 아님을 명시. 같은 기간의 공정도 실제 기간을 함께 표시.
3. 공정 수행 내역은 저장된 생성 이력(created) 시각 내림차순, ID 내림차순으로 안정 정렬. 수정이나 일정 변경은 등록순을 바꾸지 않음. 104px 카드 + 12px 간격 + 284px 목록 높이로 두 카드와 세 번째의 약 절반(52px) 노출. 제목/등록 버튼 고정. 새 공정 등록과 프로젝트 전환 시 목록 상단, 같은 프로젝트 일반 갱신 시 스크롤 보존.
4. 달력은 날짜별 체크박스와 공정명 한 줄. 체크와 상세 열기 분리, 긴 제목 말줄임, 색상 보존. 달력의 중복 진척률 표시는 제거 상태 유지.
5. 근태는 별도 등록 카드를 제거하고 달력 툴바에 출근/퇴근 버튼 배치. 데스크톱 34px, 모바일 44px. 등록 대상은 로그인한 본인 이름으로 표시하여 Admin 조회 대상과 구분.
6. 상세 표는 최초 접힘. 키보드로 조작 가능한 버튼과 aria-expanded/aria-controls 제공. 갱신 때 펼침 상태 보존. 기존 5행 페이지, KST, CSV, Admin 수정/삭제 유지.
7. 반복 페이지 제목·오늘 날짜·보조 문구의 DOM 및 갱신 코드를 제거. 시각적으로 숨긴 h1과 문서 제목 유지. 네트워크 상태는 근태 제목 옆의 작은 표시로 이동. 오류와 처리 결과 메시지 유지.
8. 상단 메뉴도 기존 모듈 색상과 aria-current로 선택 표시. 기안/보고 작성과 사용자 하위 화면의 상위 메뉴를 좌측과 동일하게 강조. 비선택/호버/키보드 포커스 구분.

## 자체 코드 리뷰와 수정

- 진척률 계산과 저장 API를 변경하지 않고 동일 projectProgress 결과를 재사용. 타임라인/등록순 목록 모두 복사한 배열을 정렬하여 원본 데이터와 다른 화면 순서를 변경하지 않음.
- 등록순은 실제 생성 이력을 조회한 created_at으로 결정. 수정 이력 시각을 생성 시각으로 오인하지 않도록 created 종류만 사용.
- 목록 재렌더 시 스크롤이 항상 초기화되던 부분을 프로젝트/최신 공정 ID 기준으로 보완. 등록/전환 때만 상단으로 이동.
- Admin이 다른 직원을 조회해도 출퇴근 등록은 기존 본인용 API를 유지. 조회 선택값을 등록 요청에 전달하지 않음.
- 접힌 표의 데이터를 갱신해도 hidden 상태는 변경하지 않음. aria 상태와 실제 표시 동기화 검증.
- 반복 제목 요소 제거 후 참조 코드를 정리하고 관련 기존 테스트를 새 사용자 표시/접이식 UI 기준으로 갱신.
- 최종 리뷰에서 미해결 권한 누락, 데이터 혼합, 계산 오류, 기능 회귀는 발견되지 않음.

## 제한

생성 이력이 없는 과거 공정은 실제 생성 시각을 복원할 수 없으므로 임의의 날짜를 만들지 않고 고유 ID 내림차순으로 정렬합니다. 생성 이력이 있는 공정을 먼저 표시합니다. 선후행 관계는 현재 저장되어 있지 않아 타임라인으로 제공합니다. Chromium 및 모바일 뷰포트 에뮬레이션을 사용했으며 실제 iOS/Safari/Firefox는 검증하지 않았습니다.
