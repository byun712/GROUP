# 문서 수정·재상신·재승인

휴가신청서, 지출결의서, 전자결재 기안 양식과 업무보고 4종에 동일하게 적용됩니다.

| 문서 상태 | 작성자 | 이사 |
| --- | --- | --- |
| 이사 승인 대기 | 문서 수정, 회수 | 승인, 반려 |
| 대표이사 승인 대기 | 조회 | 해당 회차에서 직접 승인한 이사가 승인 후 반려 가능 |
| 이사가 반려 | 문서 수정, 재상신 | 직접 반려한 이사가 반려 후 다시 승인 가능 |
| 대표이사가 반려 | 문서 수정, 재상신 | 작성자가 재상신하면 다시 심사 |
| 회수 | 문서 수정, 재상신 | 재상신 후 심사 |
| 최종 승인 완료 | 조회 | 조회 |

Admin이어도 다른 사람이 작성한 문서를 수정·재상신할 수 없습니다. 본인 문서라면 위 규칙에 따라 처리합니다. 기존의 이사·대표이사 본인 승인 기능도 유지됩니다.

## 작성자 사용 순서

1. 전자결재 또는 업무보고에서 문서를 엽니다. 반려된 문서는 **반려** 탭에서 찾습니다.
2. **문서 수정**을 누르면 원래 작성 양식에 저장된 내용을 불러옵니다.
3. 내용을 고치고 **수정 저장**을 누릅니다. 수정 취소는 저장하지 않습니다.
4. 반려·회수 문서는 상세 화면의 **재상신**을 누르고 확인합니다. 이사 승인 대기로 돌아갑니다. 이사 승인 대기 문서는 수정 저장 후 기존 대기 상태를 유지합니다.

수정 저장과 재상신은 별도 작업입니다. 반려 문서를 수정해 저장한 것만으로 결재가 시작되지는 않습니다. 이사가 직접 재승인하거나 작성자가 재상신해야 합니다.

## 이사 사용 순서

**반려** 탭에서 본인이 반려했던 문서를 열고 현재 내용을 확인한 뒤 **반려 후 다시 승인**을 누릅니다. 대표이사 승인 대기로 이동합니다. 대표이사 반려 문서는 작성자가 재상신한 후 이사 결재 대기함에서 심사합니다.

## 이력과 연동

- 문서번호는 유지됩니다. 재상신할 때마다 1차, 2차 등 회차가 증가하고 이전 승인·반려·수정·재상신 이력이 남습니다.
- 화면과 엑셀의 결재란은 현재 회차의 결재 결과와 서명만 표시합니다. 이전 회차 이력은 처리 이력에서 확인할 수 있습니다.
- 오래 열어 둔 문서에 다른 수정이나 결재가 있으면 저장·결재가 차단됩니다. 문서를 다시 조회하고 최신 내용을 확인하세요.
- 휴가 기간·종류 변경 시 평일 기준 차감 일수를 다시 계산합니다. 토·일요일, 공휴일, 근로자의 날, Admin 등록 회사 휴일을 제외합니다. 사유만 수정하거나 같은 내용으로 재상신하는 경우 기존 차감 일수를 보존합니다.
- 휴가 수정 시 본인의 해당 문서 예약분을 중복 계산하지 않습니다. 반려·회수 문서는 내용 저장이 가능하더라도, 재상신·재승인 시 잔여 일수가 부족하면 진행할 수 없습니다.
- 이사 재승인 시 휴가 사용 일수와 일정·근태 달력에 다시 반영합니다. 반려하면 해제합니다.
- 지출결의서는 최종 대표이사 승인 시 수정된 금액으로 회계에 한 번만 연동합니다.
- 대표이사가 이미 처리했던 문서의 삭제 제한은 재상신 후에도 유지됩니다. 기존 결재 자료를 보존합니다.

## 업데이트

서버를 종료하고 기존 `data` 폴더를 별도로 백업하세요. 새 프로젝트 폴더에 기존 `data` **폴더 전체**를 복사한 후 `START-LOCAL.cmd`를 실행합니다. 메일 암호화 키도 포함되므로 `group.db`만 복사하지 마세요. `node_modules`는 복사할 필요가 없습니다. 첫 실행 때 기존 문서는 1차·버전 1로 자동 이전되며 데이터는 유지됩니다. Edge에서 `Ctrl+F5`로 새 화면을 불러오세요.

검증: `npm test` 및 `scripts/document-resubmission-smoke.mjs`. 테스트는 임시 DB를 사용합니다. Chromium 브라우저 검증이며 실제 Windows/Edge 실행은 별도입니다.
