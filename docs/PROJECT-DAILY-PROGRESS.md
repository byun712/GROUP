# 날짜별 공정 관리


> 추가 변경: [Admin 공정 삭제·사용자별 근태 달력·이사 승인 휴가 연동](ADMIN-ATTENDANCE.md)을 확인하세요.
## 완료 체크와 공정률

- 프로젝트 공정 달력에서 각 날짜의 완료 체크를 독립적으로 저장합니다. 다른 날짜의 체크에는 영향을 주지 않습니다.
- 공정률 = 현재 공정 기간 내 완료 날짜 수 / 전체 공정 일수 × 100. 시작일·종료일과 주말을 포함합니다.
- 예: 4일 일정에 1일 완료 → 25%, 2일 완료 → 50%, 전부 완료 → 100%. 4일 전부 완료 후 5일로 연장 → 80%.
- 화면은 정수로 반올림합니다. 미완료 날짜가 하나라도 있으면 최대 99%이며 모든 날짜 완료 시에만 100%입니다.
- 완료 체크/해제는 수행 내역에 자동 문구를 추가하지 않습니다. 체크 상태는 재접속해도 유지합니다.
- 수동 진척률 입력과 전체 공정 완료 스위치는 제거했습니다. 상태는 완료 날짜 수에 따라 예정/진행/완료로 계산합니다.
- 프로젝트 전체 진척률은 공정별 진척률의 단순 평균입니다. 프로젝트 상태 자체는 기존대로 별도로 관리합니다.

## 수행 내역과 일정 변경

1. 날짜의 공정 이름을 클릭합니다. 담당자·기간을 수정하거나 수행 일자와 해당 일자의 수행 내용·결과를 입력합니다.
2. 공정 기간을 바꾸면 **일정 변경 사유**를 반드시 입력합니다. 저장 시 공정률이 자동으로 다시 계산됩니다. 새로 포함된 날짜는 미완료입니다.
3. 현재 기간 밖으로 빠진 완료 체크는 계산에서 제외하지만 보존합니다. 나중에 그 날짜를 다시 기간에 포함하면 기존 체크가 복원됩니다.
4. 공정 수행 내역에는 현재 조회 월과 겹치는 공정당 한 개의 대표 카드만 표시합니다.
5. 대표 공정 이름을 누르면 완료한 날짜, 일자별 수행 기록, 일정 변경 전후 기간·사유, 작성자와 기록 시각을 확인합니다. 같은 날짜에 여러 번 작성한 내용도 보존합니다.
6. 일정 조정으로 기간 밖이 된 날짜의 기존 수행 기록도 공정 상세에서 볼 수 있습니다.

모든 활성 로그인 사용자가 공동 편집할 수 있고 이전 버전으로 저장하면 409 충돌로 거절합니다. 공정 기간은 프로젝트 범위 안에서 최대 3,660일입니다.

## 기존 자료 이전

서버를 새 버전으로 실행하면 SQLite 열을 추가하고 한 번만 변환합니다. 별도 DB 교체나 초기화가 필요하지 않습니다.

기존 구조에는 날짜별 완료 정보가 없었습니다. 기존 완료 공정은 기간의 모든 날짜를 체크하고, 부분 진척 공정은 기존 진척률에 가장 가까운 완료 일수만큼 시작일부터 초기 체크합니다. 날짜 단위 전환으로 일부 비율은 반올림되어 달라질 수 있습니다. 이는 실제 과거 완료일을 복원한 것이 아니므로 상세 화면에 안내 문구를 표시하며 실제 날짜에 맞게 체크를 정리해야 합니다. 변환은 새로운 수행 내역을 만들지 않습니다.

기존 수기 수행 기록은 유지합니다. 이전 시스템이 자동으로 남긴 정확히 일치하는 `완료 체크로 공정 완료`와 `완료 체크 해제` 문구만 수행 내역 조회에서 제외합니다. 기존 기록에는 실제 수행 일자가 없으므로 과거 작성 시각과 내용을 그대로 표시합니다.

## 업데이트와 검증

기존 서버를 종료하고 새 소스를 별도 폴더에 압축 해제한 다음, 기존 `data` 폴더 전체를 복사해 `START-LOCAL.cmd`를 실행합니다. Edge에서 Ctrl+F5로 새 화면을 불러옵니다. 작업 전 기존 `data` 폴더를 별도로 보관하면 이전 버전으로 돌아갈 수 있습니다.

`npm test` 27개 통과. 새 통합 테스트는 날짜별 독립 체크, 누적/해제, 기간 확장·축소와 체크 복원, 변경 사유 필수, 작업 일자, 공동 편집 충돌, 로그인 보호, 기존 자료 이전을 검증합니다. Chromium의 `scripts/workspace-smoke.mjs`와 `scripts/business-smoke.mjs`에서 달력 체크, 자동 비율, 대표 공정 상세 내역, 변경 사유, 재접속과 모바일 화면을 검증했습니다. 실제 Windows/Edge 실행 검증은 별도입니다.
