2026-11-12. 작업 기준은 원격 main에서 확인한 `5fc41a92137adf2c470f6e4468486578d51791dc`다. 이 문서와 코드를 포함한 최신 커밋을 사용한다. 과거 카드형 회계 목록, 세 칸 프로젝트 선택 목록, 고객사 열람 팝업으로 되돌리지 않는다. 실행·데이터 보존은 [NEW-CHAT-SETUP.md](NEW-CHAT-SETUP.md), 전체 기능 인수인계는 [HANDOFF.md](HANDOFF.md)를 참고한다.

## 현재 동작

### 프로젝트 워크보드

- 선택 프로젝트의 제목은 요약 카드 맨 위 왼쪽이며 색상과 상태 배지를 유지한다. 제목에 줄바꿈·말줄임표를 적용하지 않는다. 일반적인 제목은 한 줄로 보이고, 카드보다 긴 제목은 제목 영역의 가로 스크롤·키보드 포커스·title 설명으로 전체를 확인한다.
- 정보는 `시작일 ~ 종료일`과 `진척률 N% (공정 완료수 / 전체수)` 두 행이다. 완료수는 완료 상태인 **공정 개수**이며 완료 일수가 아니다. 도넛 중앙과 정보 행은 같은 서버 진척률을 사용한다. 공정이 없으면 `0% (공정 0 / 0)`이다.
- 계산 안내 문구만 제거했다. 공정별 완료 일수/전체 일수, 프로젝트 공정률의 산술평균, 날짜별 완료 체크는 그대로다. 테스트 예: 5일 중 3일을 완료한 공정 하나와 미완료 공정 두 개 → 도넛과 정보 모두 20%, 완료 공정 0/3.
- 세 패널 높이 322px, 세로 막대그래프, 수행 내역 두 카드와 내부 스크롤, 전체 프로젝트 Excel 보고서는 유지한다. 요약 카드 내부 폭이 좁으면 도넛 아래에 정보 두 행을 둔다.
- 데스크톱 프로젝트 목록은 간격 12px, 카드 폭 `(목록 폭 − 36px) / 4`다. 카드 수와 무관하게 한 줄이며 다섯 번째부터 내부 가로 스크롤이다. 모바일/태블릿에서는 최대 280px·목록의 85% 너비를 사용한다.
- 목록의 제목/회사/기간 세 행, 상태·선택 테두리를 유지한다. 긴 목록 제목은 말줄임표와 전체 제목 설명을 제공한다. Tab, 방향키, Home/End, Enter로 탐색·선택할 수 있고 선택 변경·화면 크기 변경 시 선택 카드를 보이게 이동한다. 상세·달력·공정·그래프 갱신을 유지한다.

### 세무회계

- 미지급 승인 지출: 문서, 기안자, 거래처, 금액, 지급 상태. 지급 상태는 실제 조회 조건인 최종 승인·미지급에서 표시하며 승인일·전표번호를 만들지 않는다. 문서 클릭은 기존 지급 기록 창으로 연결되고 긴 문서/거래처 및 실제 지출일을 확인할 수 있다.
- 회계 전표: 전표일자, 실제 구분, 적요, 금액. 적요 클릭으로 기존 분개 상세·수정·삭제 기능에 접근한다.
- 각 표는 5행씩 독립 페이지를 가진다. 마지막 페이지/데이터 삭제 후 유효한 페이지로 보정하며 전표 월을 바꾸면 전표 첫 페이지로 돌아간다. 0건은 빈 행 없이 안내만 표시하고 양쪽 이동 버튼을 비활성화한다. 1건은 1행이다. 표 내부만 가로 스크롤한다.
- **기존 조회 범위 유지**: 월은 전표 표시만 필터링한다. 미지급 지출, 상단 잔액·미지급 금액·전표 수, 계정별 합계는 기존 전체 장부 기준이다. 화면 페이지 이동은 집계 입력을 자르지 않는다.

### 계정별 합계 Excel

- `GET /api/accounting/accounts/excel`, ExcelJS를 사용한 실제 XLSX. 화면과 다운로드가 `accountBalances()`의 동일한 전체 장부 집계 SQL을 사용한다. 임의의 월 조건, 다른 목록의 페이지 제한을 적용하지 않는다.
- 실제 화면 열인 계정코드·계정명·차변 합계·대변 합계 네 열과 전체 계정을 포함한다. 화면에 없던 계정별 잔액 열이나 별도 총계 행을 만들어 넣지 않는다. 상단 현금·예금 잔액의 차변−대변 계산도 변경하지 않는다.
- 제목, 전체 장부 기준·원 단위, 한국 시간 생성일시, 숫자 금액과 천 단위 서식, 긴 이름 줄바꿈·행 높이, 고정 헤더·필터, A4 인쇄 가로 폭 한 페이지·세로 자동을 설정한다. 파일명: `계정별합계_전체장부_YYYY-MM-DD.xlsx`.
- 생성 중 버튼 비활성화/진행 표시, 실패 안내, 재시도를 제공한다. 서버가 인증과 manager/ceo 역할을 검사한다. employee 및 회계 역할 없는 Admin에게 데이터/API/XLSX를 허용하지 않는다.

### 고객사·담당자

- 최초 진입/새 로그인 시 접힘. 요약 버튼은 회사명·주소(미등록 대체 문구)·담당자 수 배지와 화살표만 표시한다. 긴 회사명/주소는 요약에서 제한하고 title 및 펼친 영역에서 전체를 읽는다.
- 회사 요약을 클릭하거나 Enter/Space로 카드 안에서 펼친다. `aria-expanded`와 `aria-controls`를 갱신한다. 옆 카드는 늘어나지 않는다. 담당자 0명은 `등록된 담당자가 없습니다`를 표시한다.
- 실제 이름, 부서·직책, 전화·휴대폰, 이메일, 메모·명함을 표시한다. 이메일은 기존 메일 작성 화면의 받는 사람을 채운다. 메일/관리 버튼은 요약 토글과 분리되어 접히지 않는다.
- 등록·수정은 기존 편집 창을 유지한다. 소유자 또는 기존 운영 권한(Admin/manager/ceo)의 수정 권한을 유지한다. 담당자 등록은 기존 공동 등록 규칙을 유지한다. 수정·추가·삭제 후 목록과 인원 수를 갱신하면서 펼침 상태를 보존한다.
- 기존 코드에 없던 명시적 삭제 경로를 추가했다. 삭제는 기존 수정 권한, 버전 확인, 사용자 확인 체크가 필요하다. 담당자 또는 연결 프로젝트가 있는 고객사 삭제는 409로 차단한다. 담당자 삭제는 해당 연락처와 명함만 제거한다.
- 기존 고객사/담당자 테이블과 ID를 보존하며 `crm_sequences` 테이블을 추가한다. 시작 시 기존 최대 ID 이상으로 맞추고 이후 단조 증가시켜 삭제된 ID를 재사용하지 않는다. 이전 창의 낡은 요청이 새 연락처에 적용되는 것을 막는다.

`PLAYWRIGHT_MODULE=/opt/codex/runtimes/codex-primary-runtime/dependencies/node/node_modules/playwright/index.mjs`와 `BROWSER_EXECUTABLE=/usr/bin/chromium`으로 실행했다. 새 환경에서는 실제 도구 경로를 다시 확인한다. `UI_SCREENSHOT_DIR`로 저장 경로를 지정할 수 있다.

XLSX는 API 다운로드와 브라우저 실제 다운로드를 모두 ExcelJS로 재열람했다. 모든 계정 행/숫자가 API와 일치하고 다른 월·0원·음수 현금 잔액의 차변/대변 입력을 보존한다. 이름 앞 `=`도 수식으로 해석하지 않는다. 숫자 타입/서식, 필터/고정행, 인쇄 배율, 연도 경계의 한국 시간도 검증했다. 비로그인 401, 직원/회계 역할 없는 Admin 403, 비활성 사용자 401, manager/ceo 성공, 잘못된 HTTP 메서드 405를 확인했다. UI의 실패 안내·중복 클릭 차단·재시도도 검증했다.

### 변경 코드 리뷰와 수정

실행 결과와 별개로 변경 diff의 인증 라우팅, 기존 집계 SQL, 페이지 분리, 공정 개수와 일수의 구분, 안전한 텍스트 렌더링, CRM 권한·참조·버전 검사, 마이그레이션·데이터 보존을 직접 검토했다. 별도 독립 리뷰어의 승인을 의미하지 않는다.

- 좁은 고객사 관리 버튼에서 단어가 세로로 끊기는 문제 → 버튼 줄 단위 재배치와 단어 줄바꿈 방지, 세 폭 재검증.
- 삭제 후 SQLite ID 재사용으로 낡은 요청이 다른 연락처를 가리킬 가능성 → CRM 시퀀스 추가, 반복 초기화/재생성/낡은 ID 404/외래키 검증.
- 선택 카드 자동 이동과 스크롤 스냅의 충돌 가능성 → 스냅 제거, 선택/크기 변경 시 내부 이동과 선택 카드 경계 검증.
- 이전 UI의 열람 팝업·회계 카드·요약 문구를 찾던 기존 브라우저 검사 → 현행 버튼/표/두 행 표현으로 갱신하되 기존 업무 기능 assertion 유지.

## 남은 제한

요청된 기능 중 알려진 미완료 항목은 없다. 실제 iOS/Safari/Firefox·하드웨어 트랙패드와 Microsoft Excel/LibreOffice의 실제 인쇄는 검증하지 않았다. Chromium 모바일 폭, 키보드/가로 스크롤, XLSX 재열람/인쇄 설정 검증과 구분한다. 이 요청에 실제 첨부 이미지 파일은 제공되지 않아 텍스트 요구사항과 저장소의 기존 디자인을 기준으로 구현했다.

운영 배포나 Codex 환경 게시는 수행하지 않는다. GitHub main push와 환경 게시/새 환경 연결은 별개다. 새 채팅에서는 최신 main·문서·로컬 변경·실제 데이터 위치를 먼저 확인하고, 기존 데이터가 보이지 않으면 임의로 초기화하지 않는다.
