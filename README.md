# 모아 — 로컬 ToDo

GROUP 저장소의 `todo-standalone` 브랜치에서 배포하는 독립적인 PC 웹 앱입니다. GROUP `main`과 분리된 다운로드 버전입니다. 할 일과 업무 수행 기록을 **현재 브라우저의 IndexedDB**에 저장합니다. 로그인, GROUP API, 서버 데이터베이스, 사용자 간 공유·동기화·푸시 알림은 연결하지 않았습니다.

기존 GROUP의 HTML/CSS/JavaScript와 Node.js 도구 방식을 재사용했습니다. React/Vite나 추가 런타임 패키지를 도입하지 않았으며 이 디렉터리만으로 실행합니다. 기존 `public/` 및 GROUP 서버의 화면·동작은 변경하지 않습니다.

## ZIP을 받아 바로 실행하기

필요한 런타임: **Node.js 24 이상**. 별도 환경 변수나 비밀정보, GROUP 계정은 필요하지 않습니다. 빌드된 `dist/`를 포함하므로 처음 실행할 때 npm 설치·빌드는 필요 없습니다.

1. Node.js 24 이상이 없다면 https://nodejs.org/ 에서 설치합니다.
2. ZIP 전체를 압축 해제합니다. GitHub ZIP은 `GROUP-커밋SHA` 폴더를 만듭니다. 그 안에 `package.json`, `START-TODO.cmd`, `dist/`가 있습니다.
3. **Windows:** `START-TODO.cmd`를 실행합니다. **macOS/Linux:** 해당 폴더에서 터미널을 열고 `sh START-TODO.sh`를 실행합니다.
4. 브라우저에서 **http://127.0.0.1:4174/todo/** 를 엽니다. 서버 창은 열어 둡니다. 종료는 Ctrl+C입니다.

터미널에서 직접 실행해도 됩니다. 압축을 푼 폴더를 현재 작업 폴더로 선택한 뒤:

```sh
node --version
node scripts/serve.mjs --preview
```

`index.html`을 더블클릭하거나 ZIP 안에서 직접 실행하면 안 됩니다. 앱은 로컬 HTTP 서버를 통해 실행해야 합니다. 포트 사용 중(`EADDRINUSE`)이면 이미 실행한 ToDo 서버가 있는지 먼저 확인하세요. 다른 프로그램을 임의로 종료하지 마세요. 실행 스크립트도 `PORT` 환경 변수로 포트를 변경할 수 있지만, 포트를 바꾸면 브라우저의 저장 영역도 달라집니다. 기본은 4174입니다. Windows 실행 파일 자체는 Linux 검증 환경에서 직접 실행하지 못했으며 동일한 Node 서버와 Unix 실행 스크립트를 검증했습니다.

## 소스를 수정하며 실행하기

압축 해제한 폴더의 `package.json`이 있는 위치에서 실행합니다.

```sh
node --version
npm ci --ignore-scripts --no-audit --no-fund
npm run dev
```

추가 제품 의존성은 0개이며 `npm ci`는 포함된 잠금 파일을 확인합니다.

브라우저에서 **http://127.0.0.1:5174/todo/** 를 엽니다. 첫 화면에서 직접 할 일을 추가하거나 **예시 데이터로 둘러보기**를 선택합니다. 예시는 명시적으로 `예시` 표식을 붙이며 자동으로 생성하지 않습니다. 삭제한 예시는 새로고침해도 다시 생기지 않습니다.

개발 모드는 서비스 워커를 등록하지 않습니다. 코드를 고친 뒤 새로고침하면 반영됩니다. 개발 서버는 GROUP 서버를 시작하지 않으며 운영 DATA_DIR이나 `group.db`를 읽거나 생성하지 않습니다.

## 빌드와 PWA 미리보기

```sh
npm run build
npm run preview
```

**http://127.0.0.1:4174/todo/** 를 엽니다. 빌드는 `dist/`에 독립 정적 파일과 콘텐츠 해시로 버전을 붙인 서비스 워커를 생성합니다. 이 다운로드 브랜치는 즉시 실행할 수 있도록 `dist/`도 Git에 포함합니다. 코드 변경 후에는 다시 빌드하세요.

- 개발(5174)과 미리보기(4174)는 **다른 origin**이므로 IndexedDB 데이터도 다릅니다. `localhost`와 `127.0.0.1` 역시 다른 주소입니다. 데이터를 옮길 때 JSON 내보내기/복원을 사용하세요.
- 서버는 기본으로 `127.0.0.1`에 바인딩합니다. `PORT`와 `HOST`로 변경할 수 있지만 같은 데이터에 계속 접근하려면 주소·포트·브라우저 프로필을 유지하세요.
- 기존 운영 포트를 덮어쓰지 마세요. 새 채팅에서 이전 서버 프로세스가 계속 실행된다고 가정하지 않습니다. 사용한 터미널의 Ctrl+C로 해당 서버만 종료합니다.
- 개발과 배포에 기본의 서로 다른 포트를 권장합니다. 동일 origin을 개발용으로 재사용하면 이전 서비스 워커가 배포 파일을 제공할 수 있습니다. 이때 브라우저 개발 도구에서 **해당 `/todo/` 서비스 워커만** 해제하고 다시 로드하세요. 전체 사이트 데이터 삭제는 ToDo 데이터도 지우므로 먼저 백업해야 합니다.

## 할 일 관리

| 보기 | 조회 기준 |
|---|---|
| 전체 할 일 | 기본 미완료. `완료 포함`으로 완료까지 조회 |
| 오늘 | 한국 시간의 오늘 마감 미완료 + 기한이 지난 미완료. 두 그룹을 구분 |
| 예정 | 오늘 이후 마감인 미완료. 마감일순 고정 |
| 프로젝트 | 연결된 프로젝트별 조회. 개인 할 일 선택도 가능 |
| 완료 | 완료 항목 조회. 체크 해제로 할 일로 복원 |

검색은 제목·설명에 적용하고, 상태/우선순위 필터와 최근 등록·마감일·우선순위·제목·최근 수정순 정렬을 제공합니다. 모든 조건은 함께 적용됩니다. 전체/프로젝트에서 완료 상태를 조회하려면 `완료 포함`도 선택합니다.

- 목록 아래에서 제목을 쓰고 Enter로 추가합니다. 오늘 보기에서는 오늘, 예정 보기에서는 내일 마감으로 추가합니다. 그 외에는 마감일 없이 시작합니다.
- 행의 제목을 누르거나 키보드로 선택하면 오른쪽 상세가 열립니다. 체크, 상태, 날짜, 우선순위는 목록에서도 변경할 수 있습니다.
- 상세의 제목·설명·속성을 수정한 후 **변경사항 저장**을 누릅니다. 길어진 제목과 여러 줄 설명을 그대로 편집할 수 있습니다. 목록의 긴 제목은 설명 표시와 상세에서 확인합니다.
- **업무 수행 기록**에 수행일과 내용을 입력합니다. 여러 기록의 추가/수정/삭제가 가능하고 생성 시각은 한국 시간으로 표시합니다. 상태 변경은 실제 수행 기록을 자동 생성하지 않습니다.
- 상태가 완료로 바뀌면 완료 시각을 저장하고, 미완료로 복원하면 현재 완료 시각을 해제합니다. 동일 완료 상태에서 제목만 수정하면 기존 완료 시각을 유지합니다.
- 삭제는 확인을 거칩니다. 할 일을 삭제하면 연결된 업무 기록도 같은 트랜잭션에서 삭제합니다.
- 사이드바 프로젝트 옆 `+` 또는 프로젝트 보기의 관리 버튼에서 로컬 프로젝트와 공정을 등록·수정·삭제합니다. 공정은 프로젝트에 소속되며, 다른 프로젝트의 공정을 연결할 수 없습니다. 연결된 할 일/공정이 있으면 프로젝트나 공정을 바로 삭제하지 않습니다.

저장 실패 시 입력을 남겨 두고 오류를 표시합니다. 같은 항목을 다른 탭에서 수정한 경우 이전 버전으로 덮어쓰지 않습니다. 이 경우 현재 입력을 복사해 두고 상세를 다시 열어 최신 항목에 필요한 변경을 적용하세요. 여러 탭 간 변경 알림은 **같은 브라우저 origin 안에서만** 동작하며 서버 동기화가 아닙니다.

## 저장·백업·초기화

- DB 이름: `group-todo-local`, IndexedDB 스키마 버전: `1`.
- 저장 대상: `projects`, `processes`, `tasks`, `workLogs`, `settings`.
- 날짜만 필요한 마감일/수행일: `YYYY-MM-DD`. 생성·수정·완료 시각: UTC ISO 실제 시점, 화면은 `Asia/Seoul`.
- 운영 GROUP 데이터와 다른 저장소이며 다른 기기·브라우저·프로필에 자동 복제하지 않습니다. 브라우저 데이터 삭제, 비공개 모드 종료, 저장 공간 정리로 사라질 수 있으므로 중요한 기록은 JSON 백업을 보관하세요.

**설정 및 데이터 → JSON 내보내기**로 전체 데이터와 화면 설정을 내려받습니다. 복원은 파일 형식·스키마·ID 중복·프로젝트/공정/할 일 연결·날짜를 먼저 검증한 뒤 전체를 하나의 트랜잭션으로 교체합니다. 기존 데이터를 먼저 내보내세요. 유효하지 않은 파일은 기존 데이터를 변경하지 않습니다.

**ToDo 데이터 초기화**에서 `초기화`를 입력하면 이 DB의 데이터만 지웁니다. GROUP 서버, 다른 앱의 DB, 다른 앱의 서비스 워커/캐시는 지우지 않습니다. 초기화는 되돌릴 수 없고, 복원하려면 미리 만든 JSON 백업이 필요합니다.

## PWA와 오프라인

Manifest의 앱 ID/start_url/scope는 `/todo/`, 표시 모드는 `standalone`입니다. 아이콘은 자체 제작한 SVG와 192/512px PNG입니다.

1. HTTPS 또는 localhost/127.0.0.1에서 **배포 미리보기**를 한 번 정상적으로 엽니다.
2. 상단의 `오프라인 준비됨`을 확인합니다.
3. 설치를 지원하는 브라우저에서는 브라우저 설치 기능을 사용합니다. 브라우저가 실제 설치 가능 이벤트를 제공한 경우에만 앱 안에 `앱 설치` 버튼을 표시합니다.
4. 캐시 준비 후 네트워크를 끊고 다시 열어도 할 일을 조회·수정할 수 있습니다. 최초 로드 전의 오프라인 실행은 지원하지 않습니다.

서비스 워커는 `/todo/` 안의 명시된 정적 자산만 캐시합니다. 사용자 데이터와 API 응답은 캐시하지 않습니다. 앱 파일 업데이트는 대기하며 자동으로 편집 중인 화면을 새로고침하지 않습니다. 업데이트 버튼도 미저장 입력 또는 저장 중인 작업이 있으면 적용하지 않습니다. 다른 탭이 새 버전을 적용해도 현재 탭의 입력을 강제로 지우지 않습니다. 오래된 자산 캐시는 최근 3개 버전까지 남겨 이미 열린 탭의 사용을 돕습니다.

## 테스트

```sh
npm test
npm run build
```

브라우저 테스트는 별도 Playwright/Chromium 도구를 사용하며 제품 의존성에는 포함하지 않습니다. 이 클라우드 머신에서 확인한 실행 방법:

```sh
export PLAYWRIGHT_MODULE=/opt/codex/runtimes/codex-primary-runtime/dependencies/node/node_modules/playwright/index.mjs
export BROWSER_EXECUTABLE=/usr/bin/chromium
UI_SCREENSHOT_DIR=/tmp/todo-validation npm run test:browser
```

새 머신에서 도구 경로는 다시 확인하세요. 테스트는 임시 서버·임시 Chromium 프로필·임시 ToDo DB로 실행하며 실제 사용 중인 브라우저 데이터에 접근하지 않습니다. 기존 GROUP 회귀 테스트는 별도로 보존된 GROUP `main` 체크아웃에서 실행합니다. 이 브랜치의 `npm test`는 ToDo만 검사합니다.

[테스트 결과·PC 화면·제한](docs/VERIFICATION.md), [데이터 구조와 GROUP 연동 계획](docs/GROUP-INTEGRATION.md)을 참고하세요. **모바일 최적화, 모바일 PWA·푸시, GROUP 연결은 완료 범위가 아닙니다.**
