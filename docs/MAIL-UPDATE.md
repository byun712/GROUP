# 외부 메일과 로고 테마 업데이트

## 사용 방법

1. 서버를 종료하고 기존 `data` 폴더 전체를 별도 백업하세요.
2. 최신 파일을 새 폴더에 풀고 기존 `data` 폴더를 복사하세요. 기존 DB를 삭제하거나 새 DB로 덮어쓰지 마세요.
3. Node.js 24 이상에서 `START-LOCAL.cmd`를 실행하세요. 첫 실행은 인터넷으로 메일 패키지를 설치합니다. 직접 실행할 때는 `npm ci` 후 `npm start`를 사용합니다.
4. 로그인 → 이메일 → 계정 추가에서 카페24 계정의 **메일 비밀번호**를 입력하세요. 그룹웨어 비밀번호와 별개입니다.
5. 메일 가져오기 → 목록에서 제목 클릭 → 본문/첨부 확인. 메일쓰기에서 수신자·본문·첨부를 넣고 발송합니다.

| 항목 | 기본값 |
|---|---|
| 이메일 / 사용자 아이디 | soltec@elsoltec.com |
| POP3 | webmail.elsoltec.com, 110, 보안 사용 안 함 |
| SMTP | smtp.cafe24.com, 587, STARTTLS |

보안 방식은 각 계정 설정에서 사용 안 함 / STARTTLS / SSL·TLS를 선택할 수 있습니다. SMTP 기본값은 최신 제공 이미지의 `tls://smtp.cafe24.com`에 맞췄습니다. 실제 카페24 계정에 지정된 방식/포트를 사용하세요. 보안 사용 안 함은 연결 구간을 암호화하지 않습니다. TLS 인증서 검증은 유지합니다.

## 포함 기능

- 사용자별 복수 계정, 계정 수정, 비밀번호 변경 시에만 재입력
- POP3 UIDL 중복 방지, 1회 신규 메일 최대 30개, 수신 원본 서버 보관 (삭제 명령 없음)
- 받은/보낸/스팸/휴지통, 제목·발신자·수신자 검색, 기본 20개·20~100개까지 10개 단위 페이지
- SMTP 서명, 여러 수신자 (최대 30명), 파일 최대 10개·합계 10MB
- MIME 한국어 제목·파일명, 수신 첨부 다운로드, 본문 텍스트 표시
- 사용자별 메일 접근 제한, 비밀번호 AES-256-GCM 암호화 저장, API 응답에서 제외
- 흰 배경, 회사 로고, 태양 심볼의 주황·노랑·보라·초록·하늘색 포인트

메일은 로그인한 사용자가 직접 연결한 계정에서만 조회됩니다. 공용 사서함을 이용할 계정에 메일을 연결하세요. 개인 메일함/자동 분류/표시 개수는 [추가 안내](ACCESS-MAIL-MANAGEMENT.md)를 참조하세요. 동일 메일 계정의 사내 공유 권한 위임·IMAP 폴더 동기화·자동 주기 수신·HTML 편집·임시저장·참조/숨은참조는 이번 범위에 포함하지 않습니다. 스팸/휴지통 분류는 그룹웨어 내부에서만 적용됩니다. POP3 수신은 15MB 메시지까지 지원하며, 초과 메일은 카페24 웹메일에서 확인하세요.

## 백업

`data/group.db`와 **`data/mail-key`를 함께 보관**해야 메일 비밀번호를 복원할 수 있습니다. 키는 새 계정 연결 전에 자동 생성되며 소스/ZIP/GitHub에 들어가지 않습니다. 키가 없는데 메일 계정이 있으면 덮어쓰지 않고 시작을 중단합니다.

`node scripts/database.js backup data/group.db /별도경로/group-backup.db`는 메일 계정이 있으면 `group-backup.db.mail-key`도 만듭니다. 두 파일을 함께 이동·보관하세요. `restore` 명령은 키도 새 데이터 폴더에 복원합니다. DB 복원 후 기존 세션은 만료됩니다. DB·키는 외부에 공개하지 마세요.

## 검증 범위

로컬 가짜 POP3·SMTP 서버로 MIME 수신, 중복 방지, 원본 유지, 한국어 첨부 발송, 다운로드 접근 제어, 암호화, 백업/복원을 검사합니다. 실제 카페24 인증·외부 배달은 계정 비밀번호 입력 후 별도 확인해야 합니다. 보낸메일함의 발송 완료는 SMTP 서버 수락을 의미하며 최종 수신함 도착을 보장하지 않습니다.

로고는 제공된 시안 이미지에서 분리해 만든 투명 PNG입니다. 원본 벡터 파일이 있으면 `public/logo.png`를 교체해 사용할 수 있습니다.
